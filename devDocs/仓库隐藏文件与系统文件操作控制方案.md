# 仓库「允许操作隐藏文件和系统文件」选项 设计方案

> 建立于 2026-10-10。**状态：设计方案待用户裁定（未开工，未改任何代码）**。工作卡：`DevAgentControl/CURRENT_STATE_仓库隐藏文件操作控制.md`。
> 需求（用户原话）：「目前 MxsDoc 新建的仓库的时候如果用户选择了自定义的存储路径时，存在一个很大的风险，用户可以直接看到隐藏文件和系统文件和目录，甚至修改和删除它们，所以我希望仓库设置里可以有允许操作隐藏文件和系统文件的选项」。
> 本文所有「现状」结论均来自源码（给 `文件:行号`），不是推测。

## 1. 现状与风险成因

### 1.1 仓库文件区的根目录 = `repos.realDocPath`（可能被设成服务器上任意目录）

| 环节 | 位置 | 说明 |
|---|---|---|
| 新建仓库 | `src/com/DocSystem/controller/ReposController.java:521` `/addRepos.do` | 接收 `path`（仓库位置）与 `realDocPath`（文件存储位置） |
| 修改仓库 | `ReposController.java:1464` `/updateReposInfo.do` | 同上；参数归一化见 `:1881 formatReposInfo()` |
| 路径归一化 | `src/com/DocSystem/common/Path.java:166` `localDirPathFormat()` | `\`→`/`、盘符大写、补尾 `/`；**不校验存在性/白名单/是否越界** |
| 唯一的防线 | `ReposController.java:585` `isPathConflict(path, realDocPath)`（实现 `BaseController.java:1326`） | **只在「仓库位置」与「文件存储位置」互相包含时拒绝**；`realDocPath` 指向与仓库位置无关的任意目录（如 `C:/Users/Public/`、`C:/Windows/System32/`）**一律放行** |
| 代码作者已知该风险 | `ReposController.java:583-584` 原注释 | 「如果去除 realDocPath 的限制，文件系统前置将具备非常大的灵活性和破坏性（**可以查看和删除后台的所有文件**）」 |
| 浏览根解析 | `Path.java:512 getReposRealPath(repos)` | `realDocPath` 非空则**直接用它**；否则回落 `<仓库位置>/<reposId>/data/rdata/` |
| 浏览根使用 | `ReposController.java:2300-2302`、`DocController.java:9335 getSubDocListForRepos` | `localRootPath = Path.getReposRealPath(repos)` |

⇒ **只要「文件存储位置」自定义成某个已有目录（如某个盘/某个用户的文档目录/系统目录），该目录就是仓库文件区的根**，目录里有什么，用户就能看到什么。

### 1.2 文件列表对隐藏/系统条目**没有任何过滤**

`BaseController.java:843 getLocalEntryList(Doc doc)`（:877 `dir.listFiles()` → :878-900 逐项 `buildBasicDoc`）：**每一项都原样返回**，无 `.` 前缀过滤、无 `isHidden()` 判断。

全仓只有**一处**做过隐藏过滤 —— 系统设置的服务器目录选择器 `ManageController.java:1809`（`getServerDirList.do`，超管只读、只列目录）：
```java
if(!isShowHidden && (subName.startsWith(".") || subFile.isHidden())) continue;
```
⇒ 仓库文件区**没有**沿用这套口径，这正是本方案要补的。

### 1.3 变更操作同样没有任何「隐藏/系统」判定

写操作最终都落到 `BaseController` 的 `*RealDoc*` 一族方法（见 §4.4），路径是拼出来的字面相对路径（`localRootPath + doc.getPath() + doc.getName()`）；唯一的路径校验是 `Path.seperatePathAndName`（`Path.java:48`，只拒绝路径分量里的 `..`），**与「是否隐藏/系统文件」无关**。

⇒ 结论：`realDocPath` 自定义以后，用户既能**看到**也能**重命名/移动/复制/删除/下载**目标目录里的隐藏文件与系统文件（Windows 上典型的 `pagefile.sys`、`hiberfil.sys`、`System Volume Information`、`$RECYCLE.BIN`、`desktop.ini`、`.git`；*nix 上的 `.ssh`、`.bashrc` 等）。

## 2. 名词定义：什么算「隐藏文件 / 系统文件」

新增判定工具（`src/com/DocSystem/common/FileUtil.java`，**只此一处**，列表过滤与操作拦截共用同一口径）：

```java
//判断是否为隐藏文件或系统文件
//Windows: 目录项带 HIDDEN 或 SYSTEM 属性（DosFileAttributes，NOFOLLOW 避免跟随 junction/符号链接）
//*nix   : 名字以 "." 开头（额外兜底 File.isHidden()）
public static boolean isHiddenOrSystemFile(File file, Integer OSType)
```

判定顺序：
1. `name.startsWith(".")` → 真（Windows / *nix 都适用，覆盖 `.git`、`.gitignore`、`.env`）。
2. Windows：`Files.readAttributes(path, DosFileAttributes.class, LinkOption.NOFOLLOW_LINKS)` → `isHidden() || isSystem()`；读取异常则回落 `file.isHidden()`。
   - 这样能同时覆盖**隐藏**（`HIDDEN`）与**系统**（`SYSTEM`）属性；`File.isHidden()` 只认 `HIDDEN`，不够。
   - `NOFOLLOW_LINKS` 是为了不把 `C:/Documents and Settings`（junction）等链接**目标**的属性当成链接自身的属性。
3. 其他/兜底：`file.isHidden()`。

> 口径与系统设置目录选择器 `ManageController.java:1809` 保持一致（`.` 前缀 + `isHidden()`），只是我们**额外观测 SYSTEM 属性**（用户明确要求覆盖「系统文件」）。

## 3. 选项语义

| 项 | 内容 |
|---|---|
| 页面文案 | **允许操作隐藏文件和系统文件**（English：`Allow operations on hidden and system files`） |
| 位置 | 仓库设置页「仓库位置 / 文件存储位置」之后（与路径直接相关，就近放置） |
| 取值 | `0` = 不允许（默认）；`1` = 允许 |
| 未允许（=0）时 | ① 文件区**不显示**隐藏/系统条目（含目录）；② 针对隐藏/系统条目的**操作一律拒绝**（新建同名/上传/删除/重命名/移动/复制/下载/预览/编辑/分享）；③ 全文搜索**不索引**这类条目 |
| 允许（=1）时 | 与现状完全一致（全部可见、可改） |
| 生效时机 | **保存即生效（下一个请求）**：每次取仓库都重读配置（见 §4.2），无需重启 |
| 默认值 | `0`（含**升级后已存在的仓库**——配置文件不存在即视为 `0`） |

## 4. 实现设计

### 4.1 存储位置：仓库目录下的配置文件（**推荐**，镜像 `encryptType`）

仓库级选项在 MxsDoc 里有两种既成做法，本方案选 (A)：

| | (A) 仓库目录下配置文件 | (B) `repos` 表新增列 |
|---|---|---|
| 现有先例 | **`encryptType`（本方案最接近的同类：同为仓库设置页的一个勾选框，同样只在 `addRepos/updateReposInfo` 里传值）**、`textSearch`、`recycleBin`、`autoSyncup`、`autoBackup`、`remoteStorage`、`versionIgnore` | `state` / `lockBy` / `path` / `realDocPath` 等天然属于仓库主体属性的字段 |
| 落点 | `Path` 加路径 + `Repos` 加字段 + `getReposEx` 读取 + `addRepos/updateReposInfo` 保存 | 还要改 `ReposMapper.xml`（+classes 副本）、`initDBTable("repos")`、`config/docsystem_REPOS.json`（+classes 副本）、`getDBTabListForUpgarde` 版本分支 |
| 数据库升降级 | **零改动** | 必须随版本号触发 `DBUpgrade`（drop + 建表 + 从 JSON 回灌）；**本地 dev 库（`WebRoot/version` 已是 2.02.88，`ini/version` 相同 ⇒ 不会触发升级）会因缺列导致所有 `repos` 查询直接报错**，需手工 `ALTER TABLE` |
| 结论 | ✅ 采用（与同类参数一致，符合「同类参数必须用同一种处理方式」的硬性约束） | ❌ 不采用（本次不需要可查询性，却引入一次高风险的表结构变更） |

**(A) 的具体形态**（逐字对照 `encryptType` 的现成实现）：

| 项 | 新增/修改 | 对照的现成实现 |
|---|---|---|

| 实体字段 | `Repos.java` 加 `public Integer allowHiddenFile;`（与 `Repos.java:102 public Integer encryptType;` 同风格，fastjson 直接序列化给前端） | `Repos.java:102` |

### 4.2 后端判定工具（`BaseFunction`，全局唯一）

```java
//仓库是否允许操作隐藏/系统文件
protected static boolean isAllowHiddenFileOp(Repos repos) {
    return repos != null && repos.allowHiddenFile != null && repos.allowHiddenFile != 0;
}

//未开启选项时，检查目标条目（含其各级父目录分量）是否为隐藏/系统条目；命中则报错并返回 false
//dst 可为「尚不存在」的目标（新建/重命名），此时只能命中 "." 前缀规则
protected boolean checkHiddenFileAccess(Repos repos, Doc doc, ReturnAjax rt) {
    if(isAllowHiddenFileOp(repos) || doc == null) return true;
    String rootPath = doc.getLocalRootPath();
    if(rootPath == null || rootPath.isEmpty()) rootPath = Path.getReposRealPath(repos);
    //逐级：rootPath + path 的每一个前缀 + 末级 name
    //命中 → docSysErrorLog("该目录或文件为隐藏/系统文件，当前仓库不允许操作！", ErrorCode.NO_PERMISSION, rt); return false;
}
```
要点：
- **逐级检查**（`path` 的每一层 + 末级 `name`）—— 防止用户用 `getSubDocList?path=.git/objects/` 之类的**手工请求**绕过「列表不显示」（列表只挡 UI，不挡 API）。
- 未命中（父目录都正常）时 DFS 深度 ≤ 路径层数，每层 1 次 `File` 判定，开销可忽略。
- 移动/复制**源与目标都要查**（两次调用）。

## 10.4 本轮踩到的一个坑（**已写进 `CLAUDE.md`**）

命令行 `javac` **必须带 `-g`**：Eclipse 默认生成 `LocalVariableTable`（`.settings/org.eclipse.jdt.core.prefs` 里 `debug.localVariable=generate`），而 `javac` 不带 `-g` 时**不生成局部变量表** ⇒ Spring MVC 无法解析这些控制器的参数名，凡是带 `String/Integer/Long` 形参的端点直接 **500**（`IllegalArgumentException: Name for argument type [java.lang.String] not available...`）。本次首次命令行编译漏了 `-g`，导致 `addRepos.do` 等 500；加 `-g` 重编译并重启后恢复正常。
