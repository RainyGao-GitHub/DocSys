# 邮件服务配置改造方案（对齐短信服务的多供应商方案）

> 目标：把「邮件服务」从「properties 里 3 个键 + 只能明文/STARTTLS 的 SMTP」升级为
> **可配端口与加密方式、配置入库、可试发、可扩展多供应商**的形态，
> 复用短信多运营商方案（`devDocs/短信服务多运营商配置方案.md`）已验证的结构与验证方法。
>
> 本文档是**规划稿**：§2 的设计与 §5 的里程碑待用户确认后开工，§9 为实施记录（开工后逐里程碑追加）。

## 1. 现状调研（事实）

### 1.1 调用链

唯一发信实现：`commonService/EmailService.java`（`@Controller @RequestMapping("email")`，方法 `sendEmail` / `sendEmailEx`）。

| 调用方 | 场景 | 结果处理 |
| --- | --- | --- |
| `UserController.java:508` | 注册 / 找回密码的邮箱验证码 | 忽略返回，随后 `writeJson` |
| `BaseController.java:3498` | 邮箱验证（`verifyEmail` 类） | 直接 `return` 该布尔值 |
| `BussinessController.java:328` | 分享文件给他人时通知 | **结果被丢弃**（只塞进局部 `rt`） |
| `BussinessController.java:558` | `sendDocShareLinkByMail()` | 返回布尔值 |
| `ReposController.java:1106` | `sendEmailEx`：把加密配置文件当**附件**发给用户 | 无返回使用 |
| `SalesBase.java:2071 / 2139 / 2172` | 销售通知（含分渠道文案） | 忽略/局部使用 |

- 正文由调用方用 `channel.buildMailContent(...)` / `buildDocShareMailContent(...)` 生成，**URL 编码**后传入；服务端 `URLDecoder.decode(content,"UTF-8")` 再套 `getEmailHtmlByCode()` 模板。
- 与短信不同的是：邮件**暂无 Provider 抽象**，`EmailService` 里直接组装 JavaMail 对象。

### 1.2 配置存储事实

- UI（`tmpl/systemEmailConfig.html`）只有 **3 个框**，对应 `docSysConfig.properties`：`mail.smtp.host` / `fromuser` / `frompwd`。
- 同文件里 UI **管不到**但实际生效的键：`mail.smtp.auth=true`、`mail.smtp.starttls.enable=true`、`messagetype=text/html;charset=gb2312`、`appendEmail=$ft$`（用途待查）。
- 读写都落在 **classpath 副本**（Tomcat 下 `WEB-INF/classes/docSysConfig.properties`）：`ReadProperties.read()` 走 classloader 根；保存流程是「classes → `docSys.ini` 临时文件 → 改键 → 拷回 classes」。
- `docSys.ini/docSysConfig.properties` 里也有同一批键，但**邮件代码不读它**（只有短信迁移用了 `getDocSysIniPath()`）。

### 1.3 运行时事实（决定"为什么配了不通"）

| 事实 | 影响 |
| --- | --- |
| 没有 `mail.smtp.port` → **默认 25** | 需要 465/587 的邮箱必然失败 |
| `mail.smtp.starttls.enable=true` 已开 | 走 25 + STARTTLS；但**云主机默认封禁出站 25 端口**，通常直接超时 |
| `fromuser` / `frompwd` / `messagetype` 是 **static**，类加载时读一次 | 改「邮箱/密码」**必须重启**才生效；而「服务器」是每次发信现读 → 两个框行为不一致，极易误判"保存没生效" |
| 发件人 = 登录账号（`fromuser` 同时当 From 与认证用户） | 不能配显示名 / 独立发件地址 |
| 无 `mail.smtp.connectiontimeout` / `timeout` | 端口被 drop 时会长时间挂住，前端一直转圈 |
| 失败只返回「发送系统邮件失败！」 | 原因只进 `Log.debug(e)`（级别默认 debug，会落盘，但管理员看不到） |
| UI 无「发送测试邮件」 | 用户无法自助定位（短信页有，可直接照搬形态） |
| `messagetype` 若缺键/为空 → `setContent(.., null)` NPE | 一律失败，且原因被吞 |

**依赖库能力已核实**（解包确认，无需新增 jar）：
- `WEB-INF/lib`：`mailapi.jar` + `smtp.jar`（+`activation-1.1.1.jar`），版本 **JavaMail 1.4.4**，**只有 SMTP provider**（收信 POP3/IMAP 不涉及）。
- `com/sun/mail/smtp/SMTPTransport.class` 含 `.starttls.enable`、`.ssl.enable`、`.port`、`.starttls.required`；jar 内另有 `SMTPSSLTransport`。
- `com/sun/mail/util/SocketFetcher.class` 含 `.connectiontimeout`、`.timeout`。
- ⇒ **465/SSL、587/STARTTLS、25 明文、超时 都能通过配置项实现**，瓶颈只在"UI 不给配 + 代码写死"。

### 1.4 死代码（已核实无调用方，全项目无 `emailConfig.properties` 文件）

| 位置 | 说明 |
| --- | --- |
| `util/EmailUtil.java` | 读不存在的 `emailConfig.properties`、硬编码"自由团队"激活模板、**还把整份配置打印到 stdout**；文件读不到时异常被吞后仍 `return true` |
| `BaseController.getEmailProps()` | 无任何调用方 |
| `entity/MyEmail.java` | 仅被 `EmailUtil` 引用 |

## 2. 方案设计

### 2.1 配置存储：入库 `system_setting`（键前缀 `mail.`）

| 键 | 内容 |
| --- | --- |
| `mail.enabled` | 是否启用（关闭后所有发信直接失败并给出明确原因） |
| `mail.provider` | `smtp` / `aliyun` / `tencent` / `http` |
| `mail.from` | 发件地址（默认 = 认证账号） |
| `mail.fromName` | 发件人显示名（可选，D5） |
| `mail.smtp` | `{"host":"","port":465,"encryption":"ssl","account":"","password":"","auth":true}` |
| `mail.aliyun` | `{"accessKeyId":"","accessKeySecret":"","accountName":"","regionId":""}` |
| `mail.tencent` | `{"secretId":"","secretKey":"","region":"","fromEmailAddress":""}` |
| `mail.http` | `{"url":"","method":"POST","paramNames":{...},"params":{},"successField":"","successValue":""}` |
| `mail.options` | `{"contentType":"text/html;charset=UTF-8","connectTimeoutMs":10000,"readTimeoutMs":30000}` |

约定与短信完全一致：`null`/空串按未填处理、逐字段兜底到内置默认、读表异常静默兜底不影响启动、写后缓存失效、**表内有值即只读表**。

### 2.2 后端结构（镜像短信）

```
commonService/mail/
├── MailProvider.java            接口：buildRequest(MailConfig, MailMessage) / parse(...)
├── MailMessage.java             to / subject / htmlContent / attachments / fromName
├── MailProviderType.java        枚举：显示名、默认端口与加密方式、必填字段
├── MailEncryption.java          枚举：NONE / STARTTLS / SSL
├── MailConfig.java + MailSmtpConfig / MailAliyunConfig / MailTencentConfig / MailHttpConfig / MailOptions
├── MailConfigForm.java          表单 ↔ 配置（纯函数，可脱网验证）
├── MailSender.java              @Component（子容器）：选 Provider、统一超时/日志/结果封装
└── impl/SmtpMailProvider.java / AliyunMailProvider.java / TencentSesProvider.java / HttpApiMailProvider.java
service/mail/MailConfigStore.java  @Component（root 容器，故放 service 子包）—— 校验 / 提醒 / 种子迁移 / 有效值兜底
```

要点：
1. **不再把整份 `docSysConfig.properties` 丢给 `Session.getInstance`**，改为显式构造 JavaMail 属性：`mail.smtp.host/port/auth/starttls.enable/ssl.enable/connectiontimeout/timeout`，并按加密方式决定 `mail.transport.protocol`（`smtp` / `smtps`）。
2. **去掉 static**：每次发信现取配置 → 改完即时生效（修 P3）。
3. `EmailService.sendEmail/sendEmailEx` **签名保持不变**，内部委托 `MailSender` → 6 个调用方零改动。
4. 失败原因结构化返回（provider / providerCode / providerMsg / raw 截断），供管理页试发与日志。
5. 阿里云 DirectMail 的签名与短信 V3（`Acs3Signer`）同源，可**直接复用**；腾讯云 SES 复用短信 M8 的 TC3 签名器（若 M8 已落地）。

### 2.3 Provider 矩阵

| Provider | 发信方式 | 必填 | 说明 |
| --- | --- | --- | --- |
| **SMTP** | 25 明文 / 587 STARTTLS / 465 SSL | host、port、加密方式、账号、密码（163/QQ 为**授权码**） | 覆盖自建与企业邮箱；`mail.smtp.ssl.trust` 可选 |
| 阿里云邮件推送 DirectMail | HTTP API + 签名 | AK/SK、发信地址、区域 | 云主机封 25 时的稳妥选择 |
| 腾讯云 SES | HTTP API（TC3 签名） | SecretId/Key、区域、发信地址 | 同源复用短信签名器 |
| 自定义 HTTP 网关 | 用户自填 URL/方法/参数映射/成功判定 | 同短信 custom | 内网网关场景 |

### 2.4 管理页 UI（复用短信页形态）

- 表格「**参数 | 配置值**」两列、一个参数一行；按 provider 分 `<tbody>` 块显隐（`<div>` 会被 HTML 解析器提出表格，短信页踩过）。
- 字段：启用、供应商、发件人/显示名、SMTP（host/端口/加密方式/账号/密码）、各 API 供应商字段、高级（正文编码、连接/读取超时）。
- **「发送测试邮件」**按钮 + 弹窗（结构照搬 `systemSmsTestSend.*`）：填收件邮箱 → 回显 供应商/返回码/返回信息/耗时/原始响应（截断）。
- 编辑/保存/取消沿用页面头部按钮与「**只读字段跳过**」的收集逻辑；**hidden 字段也必须 `disabled`**（否则只读态会把表单值误判为"已填写"，这是短信 M6 踩过的真 bug）。
- 旧接口兼容：`host/email/pwd` 三参数保存仍可用，映射到 SMTP 组。

### 2.5 接口

| 接口 | 形态 |
| --- | --- |
| `getSystemMailConfig.do` | `{config, providerTypes, warnings, errors}` |
| `setSystemMailConfig.do` | 结构化字段 + 旧 `host/email/pwd`；校验失败返回错误并保持编辑态 |
| `testSystemMailConfig.do` | `toEmail` + 可选表单值；成功 `{provider, providerCode, providerMsg, elapsedMs, raw}`，失败 `rt.setError(原因)` |

### 2.6 安全与稳健性

- 密钥不落日志；失败原因回显但截断（≤1000 字符）。
- 连接/读取超时默认 10s / 30s（修 P7）。
- **不自动重试**（试探性发送重复投递会打扰收件人，且 SMTP 的失败多为配置/权限问题，重试无意义）—— 与短信"5xx/网络异常才重试"的策略刻意不同，此处 D7 待裁定。
- 收件人脱敏记日志（`ab***@example.com`）。

## 4. 存量兼容与迁移

1. **首次种子（幂等）**：当表内**没有任何 `mail.*` 行**时，从 `docSysConfig.properties`（**classpath 副本**，与现有运行时读取路径一致）一次性迁移：
   | 旧键 | 新键 |
   | --- | --- |
   | `mail.smtp.host` | `mail.smtp.host` |
   | `fromuser` | `mail.smtp.account` + `mail.from` |
   | `frompwd` | `mail.smtp.password` |
   | `mail.smtp.starttls.enable=true` | `mail.smtp.encryption=starttls`（否则 `none`）|
   | （无 `mail.smtp.port`）| `mail.smtp.port=25`（D8）|
   | `messagetype` | `mail.options.contentType`，其中 `charset=gb2312` → **UTF-8**（D4）|
   | `mail.smtp.auth=true` | `mail.smtp.auth=true` |
   | （无对应旧键）| `mail.fromName` 留空 |
2. 表内有值后**只读表**，UI 保存不再回写 properties；properties 仅作未迁移/降级兜底（读表异常时仍能发信，保证升级不炸）。
3. 升级后手改 `docSysConfig.properties` 的邮件键**不再生效**（与短信一致的运维须知，页面留静态说明）。
4. 零人工迁移：管理员不需要做任何操作，首次访问即完成种子。

## 6. 验证方案

1. **脱网探针**（纯函数，无网络）：配置装配与兜底、校验规则、迁移映射、SMTP 属性构造（三种加密 + 超时）、响应/异常归类、正文字符集（UTF-8 / gb2312 兼容）。
2. **本地假 SMTP 服务器**（新增 `%TEMP%\docsys_chk\MailStubServer.java`）：
   - 会话：`220` 问候 → `EHLO`（按需宣告 `STARTTLS` / `AUTH PLAIN LOGIN`）→ `AUTH` → `MAIL FROM` / `RCPT TO` / `DATA` → `250`
   - 可切换：是否支持 STARTTLS（自签证书）、是否 465 隐式 SSL、是否对哨兵收件人回 `550`
   - 断言：发件人/收件人/主题/正文编码（含中文）、附件可读、超时行为、失败原因透传
3. **容器内 E2E**：注册页取码（走 `UserController`）→ 桩收到邮件；管理页「发送测试邮件」→ 面板回显；保存后**不重启**即刻生效；旧三参数保存兼容；英文页。
4. **回归**：12 个菜单页切换正常、窄屏布局不受影响（若沿用短信页的表格样式）。

## 8. 风险

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| JavaMail 1.4.4 偏老 | 新版邮箱要求 TLS1.2+，465 SSL 或 STARTTLS 握手可能被拒 | 已核实支持 `ssl.enable`/`starttls.enable`；先在桩上验证，真机失败再评估升级 `javax.mail.jar`（注意与现有 `mailapi/smtp` 双 jar 的冲突） |
| 云主机封 25 端口 | 现状配置必然超时 | 这正是本方案要解的（可配 465/587；必要时用 API 型供应商） |
| 自签证书 | 桩服务器用自签证书 | 测试时配 `mail.smtp.ssl.trust=*`（仅测试环境） |
