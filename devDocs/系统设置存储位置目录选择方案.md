三条重要推论，直接影响设计：

1. **页面上的 input 显示的是「生效值」而不是原始 ini 值**（`getSystemInfo()` 调的是 `Path.getXxx()`，会套默认值）。所以：
   - 输入框里**永远是一条合法的绝对路径**（不会出现空值）⇒ 目录树可以直接按这个值定位 ✔
   - 但反过来说：**第一次点「保存」会把「默认值」固化成显式配置**（写进 ini）。这是既有行为，方案不改变它，但要写进说明。
2. `Path.localDirPathFormat()`(:166) 会把路径统一成：`\`→`/`、盘符大写、**结尾带 `/`**、空值→`/`（Windows 下非盘符的相对路径会被拼成 `C:/…`）。⇒ **对话框选择结果按同一格式给（`/` 分隔 + 尾 `/`）**，后端存盘时还会再归一化一次。
3. 这些是**服务器本机绝对路径**，不是仓库内路径 ⇒ **不能用仓库目录树（zTree）**，必须做「服务器文件系统目录树」。

### 2.3 后端接口（新增 1 个只读接口 + 可选 1 个建目录接口）

**① 列目录（P1）**

```
POST /DocSystem/Manage/getServerDirList.do
  参数：path        绝对路径；空 = 只返回根列表
        showHidden  0/1（默认 0）
  鉴权：superAdminAccessCheck(authCode, "docSysInit", session, rt)
  返回：{ status:"ok", data:{
            path, parentPath,          // 归一化后的当前路径 / 上级（根时为 null）
            roots:[ "C:/", "D:/" ],    // 仅当 path 为空：Windows = 盘符列表；Linux/macOS = [ "/" ]
            dirs:[ {name, path} ],     // 只含目录
            total, truncated           // 截断信息（P2）
        } }
```

- 实现要点：`new File(path)` → `isDirectory()` 校验 → `listFiles()` → 过滤 `isDirectory()` → 排序 → 归一化（与 `Path.localDirPathFormat` 同口径：`/` 分隔、盘符大写、尾 `/`）。
- **不返回文件**、**不返回文件内容**、**不做任何写操作** ⇒ 只读、最小暴露面。
- ⚠️ 不返回 `hasChildren`：探测子目录要额外一次 IO；改为前端「首次展开才请求」，展开后为空则显示空态。
- 该接口未进 `MyInterceptor.allowedUrl[]` 白名单也没关系：管理页走 jQuery ajax（自带 `X-Requested-With`）会被放行，鉴权由 `superAdminAccessCheck` 兜底（这条口径见仓库记忆 `manager-admin-ui.md`）。

**② 新建目录（P2，可选）**

```
POST /DocSystem/Manage/createServerDir.do   参数：parentPath, name
校验：name 非空、不含 / \ : * ? " < > |、父目录必须存在且是目录、目标不存在
返回：新建后的完整路径（前端直接回填并展开）
```

### 2.5 安全 / 跨平台 / 边界

- **安全**：新接口只增「列目录名」这一项能力，且仅超管可用。管理员本来就能把任意路径填进这 5 个字段（等价于指定数据落盘位置），所以**不构成权限提升**；但仍坚持：只读、只列目录、不返回文件内容、不做递归遍历。
- **跨平台（重点：根节点不一样）**：
  - **Windows**：根 = `File.listRoots()` 的盘符（多根），路径形如 `C:/DocSysReposes/`（`localDirPathFormat` 会把盘符字母大写）。
  - **Linux / macOS**：**根只有 `/` 一个，界面不应出现“盘符”概念**（也无 `C:` 这类东西）；路径形如 `/data/DocSysDB/`。
  - 实现口径：**后端用 `OS.isWinOS(OSType)` 分支产出 `roots`，前端只渲染它**（不在 JS 里嗅探 UA / 判断系统）——这样 *nix 与 Windows 共用同一套对话框代码，不会出现“Linux 上也画一排盘符”。
  - *nix 下额外注意：以 `.` 开头的目录默认隐藏（P2 开关）；`/` 下系统目录很多，目录树只展开一层，不做递归。
  - Windows 的 UNC（`\\server\share`）**暂不支持**（`localDirPathFormat` 会把非盘符的相对路径拼成 `C:/…`），对话框会提示“请选择本地绝对路径”。
- **符号链接/挂载**：只按需展开一层，不做递归，不会死循环。
- **超长路径/无权限**：`listFiles()` 返回 `null` 时按空列表处理并提示（不要抛异常）。
- **集群/多节点**（重要）：这 5 个键写在**本节点**的 `docSysConfig.properties`（ini + classes 各一份），**不会同步到其它节点**⇒ 多节点部署需逐节点设置；页面可加一句说明（P2 可选）。
- **不改变生效语义**：5 个键都是「下次请求生效」；本次只做选择器，不做"保存即生效"改造（若要改造属于另一个任务，见 §6）。
- **⚠️ 测试环境注意**：E2E 验收会真实写入 ini + classes（`docSys.ini/docSysConfig.properties` 与 `WEB-INF/classes/docSysConfig.properties`）⇒ 测试**必须先备份这两份、测完还原**，否则会污染 dev 环境（例如把仓库默认存储位置指到临时目录）。

## 4. 验收口径（可脚本断言）

1. **接口**：登录超管 → `POST getServerDirList.do {path:"C:/", showHidden:1}` 返回的目录集合与 `cmd /c dir /b /ad C:\` **完全一致**（实测 27/27 命中；顺序为与大小写无关的升序）；不带 `showHidden` 时默认隐藏 `isHidden()` 与 `.` 开头的目录（实测 `C:\`：20 / 27）；`path` 传空返回盘符列表；`path` 传不存在目录 → `dirs:[]` 且不是 500。
1b. **跨平台根节点**：`path` 传空时 —— Windows 返回多个盘符（`C:/`、`D:/`…）；**Linux / macOS 只返回 `["/"]`**（无盘符），且界面直接展开 `/`、不出现任何盘符节点。若 dev 环境只有 Windows，可在接口层用一个临时参数/单测模拟 `OSType=Linux` 分支核对。
2. **鉴权**：不带会话/非超管调用 → 返回 JSON 失败（`status != "ok"`），且**不泄漏任何目录名**。
3. **UI**：系统设置 → 编辑 → 点「仓库默认存储位置」的「选择…」→ 树自动展开定位到当前值；展开 `C:/TomcatForDocSysDev` 的子目录与磁盘一致；单击某目录 → 「已选」显示完整路径 → 「确定」→ input 值 = 该路径（`/` 分隔、带尾 `/`）。
4. **落盘**：点页面「保存」→ `docSys.ini/docSysConfig.properties` 与 `WEB-INF/classes/docSysConfig.properties` 对应键更新（注意 `indexDBStorePath→DBStorePath` 等 4 处映射）；刷新页面后值保持。**测完还原为原值**。
5. **编辑态**：非编辑态下 5 个「选择…」按钮 `disabled`；「取消」后 input 回到进入编辑态前的值。
6. **英文页** `_en.html` 同步生效（按钮文案 + 对话框文案）。
7. **回归**：`系统设置` 其余字段（版本/服务器/最大上传线程数/系统升级/禁用系统/清除锁定）行为不变；本方案不改保存链路 ⇒ `setSystemInfo.do` 的白名单提交仍按 `SYSTEM_INFO_FIELDS`。
8. ⚠️ **不要用 md5 判断配置是否还原**：`setSystemInfo` 用 `Properties.store()` 重写文件，**文件头的时间戳注释行**（`#Fri Oct 09 22:03:33 CST 2026`）每次都刷新 ⇒ 即使键值完全不变，md5 也会变。已实测：保存→还原后两份文件 `len=1310`、键值行与顺序与原文件逐行一致，仅时间戳行不同。

## 5. 风险

- **保存链路脆弱点（既有）**：`setSystemInfo.do` 对字符串参数是「传 null 才不改，空串=改成空」⇒ 任何新增字段都必须走 `postSystemInfo` 的白名单提交；本方案**不新增保存字段**，只是给已有 input 赋值，风险低。
- **测试会改真实配置**：见 §2.5 最后一条（必须备份/还原）。
