# 日志管理：导出功能方案

> 状态：**已裁定，实施中**（裁定 2026-10-06）
> 目标：在「管理后台 → 日志管理」页增加**日志导出**，导出**当前筛选条件（时间范围 + 关键字）下的全量日志**。

---

## 1. 现状（已核对源码）

### 1.1 页面

- 入口：侧边栏顶层「日志管理」（`tmpl/sidebar.html:15`，`data-eb-params="systemLog"`）
- 模板：`WebRoot/manager/tmpl/systemLog{,_en}.html`
  - 顶部工具条：快捷范围（今天/昨天/近7天/近30天）+ 日期区间（`#systemLogStartDate` / `#systemLogEndDate`）+ 关键字（`#search-systemLog`）+ 搜索按钮
  - 表格列：`# / 用户 / 操作 / 操作结果 / IP地址 / 时间 / 详情 / 操作(删除)`（每行可删）
  - 分页：`#systemLogList-pagination`，每页 `gPageSize = 15`（`main.js:98`）
- 前端逻辑：`main.js` 的 `showSystemLogList(pageIndex)`（`:5838`）、`SystemLogListDisplay`、`formatSystemLogContent`、`setSystemLogTimeRange`、`searchSystemLog`、`delSystemLogConfirm`；筛选状态存 `systemLogStartTime/EndTime/systemLogSearchWord`

### 1.2 数据与后端

- **存储**：Lucene 索引，**按月一个目录**：`<SystemLogStorePath>/SystemLog-<year>-<month>/`
  - `Path.getSystemLogStorePath(OSType)`：读 ini 键 **`SystemLogStorePath`**；为空则默认 Windows `C:/DocSysLog/SystemLog/`、Linux/macOS `/data/DocSysLog/SystemLog/`
  - ⚠️ 该键是 **per-node 的本机配置**（见 `devDocs/参数存储策略与参数清单.md`）⇒ **导出的只是当前这台 MxsDoc 的日志**
- 查询：`BaseFunction.querySystemLogsByTimeRange(startTime, endTime)`（`:5967`）
  - 逐月打开索引 → `NumericRangeQuery("time", start, end)` → `TopDocs(hits, 500000)` → `LuceneUtil2.buildObjectForDocument` 映射为 `SystemLog`
  - **全量结果一次性载入内存**（最多 50 万条）
- 接口：`Manage/getSystemLogList.do`（`ManageController:4230`）
  - 参数 `startTime` / `endTime` / `searchWord` / `pageIndex` / `pageSize`（`pageSize` 无上限）
  - **每次请求都重新打开索引、重新全量查询**，然后在内存里过滤 + 分页
- 实体 `SystemLog` 字段（16 个）：
  `id / time / ip / userId / userName / event / subEvent / action / result / reposName / path / name / newPath / newName / content / queryId / commitInfo`

## 2. 方案对比（落地方式）

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **A. 前端 Blob** | 一次 `getSystemLogList.do`（`pageSize` 传大值）拿全量 → 前端拼 CSV/JSON → `Blob` 下载 | **零后端改动**（不用编译/重启）；与「系统参数导出」同一套路 | ① 全量 JSON 过网络（中文多，10 万行可达几十 MB）② 服务端仍全量载入内存 ③ 行数上限只能靠前端提示 |
| **B. 服务端流式导出（推荐）** | 新增 `Manage/exportSystemLogList.do`：服务端查询一次 → **直接向响应写 CSV**（逐行 flush）+ `Content-Disposition: attachment` | ① 内存/网络最优（不构造大 JSON）② 可做**硬上限与截断提示**③ 文件名/编码（UTF-8 BOM）规范统一 ④ 便于以后加「只导出某些字段」等参数 | 新增后端代码 → 需**编译 + 重启 dev**；与前端导出相比多一个端点 |
| C. 导出 Lucene 索引原文件（zip） | 打包月度索引目录 | 可保留全部原始信息 | 用户拿到的是一堆可执行文件，**不能直接用 Excel/文本看** ✗ 不实用 |

**推荐 B**：日志量天然大（`addSystemLog` 在登录、文档操作、管理操作里到处都在写），A 的大 JSON 传输与「每次分页都重新全量查询」的组合在生产上会很难受。

---

## 3. 推荐设计（方案 B）

### 3.1 接口

```
POST /DocSystem/Manage/exportSystemLogList.do
  startTime  （必填，毫秒）
  endTime    （必填，毫秒）
  searchWord （可选，与页面一致：匹配 userName/action/content/event）
→ 直接返回文件流（text/csv;charset=UTF-8），响应头：
   Content-Disposition: attachment; filename="SystemLog_20261001-20261006_20261006143000.csv"
```

- 权限：与 `getSystemLogList.do` 一致（`userAccessCheck` + 管理员校验）；未登录/无权限时返回 JSON 错误（不下载空文件）
- **不在响应里塞 JSON**（下载接口写 JSON 会让浏览器存成 `.json`/乱码）

### 3.2 内容

- **CSV（UTF-8 + BOM）**，Excel 可直接双击打开；字段全部导出，列头跟随界面语言：

| 列 | 来源 |
| --- | --- |
| 时间 | `time` → `yyyy-MM-dd HH:mm:ss` |
| 用户 / 用户ID | `userName` / `userId` |
| IP | `ip` |
| 事件 / 子事件 | `event` / `subEvent` |
| 动作 / 结果 | `action` / `result` |
| 仓库 | `reposName` |
| 路径 / 名称 | `path` / `name` |
| 新路径 / 新名称 | `newPath` / `newName` |
| 内容 | `content` |
| queryId / 提交信息 | `queryId` / `commitInfo` |
| id | `id` |

- **转义**：字段含 `,` `"` 换行 → 用 `"` 包裹并把内部 `"` 变 `""`（`content`/`commitInfo` 里可能有多行）
- 行序：按 `time` 升序（或与页面一致的时间倒序 → **待裁定**）

### 3.3 上限与提示

- **硬上限 10 万行**（常量，可调）：超过则只写前 10 万行，并在文件首行加注释行 `# 结果被截断：仅导出前 100000 条，请缩小时间范围`（或直接拒绝并返回错误提示）
- 空结果：仍生成只含列头的 CSV（用户能确认"确实没有日志"），或返回错误提示 → **待裁定**

### 3.4 前端改动

- `tmpl/systemLog{,_en}.html`：工具条加「导出」按钮（与「搜索」同一行）
- `main.js`：`exportSystemLog()` —— 用当前 `systemLogStartTime/EndTime/systemLogSearchWord` 拼 URL 触发下载（`window.location` 或隐藏 `<form>` POST；**不能用 ajax**，否则拿不到文件下载）
  - 大范围导出耗时较长 → 按钮置灰 + 「正在导出，请稍等…」提示（下载完成与否前端无法直接感知，可给**同步提示**）
- i18n：`web/lang/en.js` 补词条

### 3.5 不做/暂不做

- 不提供 XLSX（POI 生成 xlsx 可行，但 CSV 已满足"能看能筛选"；如需要可后续加）
- 不做「导出后清空日志」（危险操作；页面已有逐条删除）
- 不合并集群各节点日志（`SystemLogStorePath` 是 per-node；如需跨节点，要另设计）

## 6. 实施记录

### 6.1 日志导出（D1~D9）

**后端**——`ManageController` 新增 `POST /Manage/exportSystemLogList.do`：

- 参数 `startTime` / `endTime` / `searchWord` / `lang`；权限与 `getSystemLogList.do` 一致（`userAccessCheck`）
- 查询→过滤复用同一套口径：抽出 `filterSystemLogsBySearchWord(list, searchWord)`，**列表与导出共用**（避免两边口径漂移）
- 空结果 → JSON 错误「没有可导出的日志！」；超 `LOG_EXPORT_MAX_ROWS = 100000` → JSON 错误并给出条数
- 通过后：**流式写 CSV**（每 1000 行 flush 一次，不构造大 JSON）
  - `Content-Type: text/csv;charset=UTF-8`，`Content-Disposition: attachment; filename="SystemLog_<起>-<止>.csv"`，`Cache-Control: no-cache`
  - 首字节写 `\uFEFF`（BOM）→ Excel 双击不乱码
  - 列头：中文/英文两套常量，按 `lang` 选（D5）
  - 转义：`csvField()` —— 含 `,` `"` `\r` `\n` 时用双引号包裹，内部 `"` → `""`
  - 行序：`time` 倒序（`Comparator`，null 视为 0）
- **不写系统日志**（D9）

**前端**：

- `tmpl/systemLog{,_en}.html`：搜索按钮旁加「导出 / Export」按钮（`#btnExportSystemLog`）
- `main.js`：新增 `exportSystemLog()`（`fetch` POST → **正向判断 `Content-Type: text/csv`**：命中即 `blob` 下载，**任何非 CSV 都进错误分支**）+ `downloadBlobAsFile()`
  - 导出中按钮置灰；文件名优先取响应的 `Content-Disposition`
  - 请求头带 `X-Requested-With: XMLHttpRequest`（与 jQuery ajax 一致，见 §6.3 坑 1）
  - 错误分支：先试 `JSON.parse` 取 `msgInfo`，非 JSON（HTML）则提示「登录状态可能已失效，请重新登录后再试」
- `web/lang/en.js`：补「正在导出，请稍等...」

### 6.2 调试日志下载（D10）

**根因**：原 `downloadLogFile.do` 返回的是 `/DocSystem/Doc/downloadDoc.do?vid=...&path=...` 链路。日志文件不在仓库里，该链路需要仓库/文档上下文 → 下载失败（即遗留的「下载 500」）。

**改法**（保持前端契约不变，只换服务端返回的 URL）：

- `downloadLogFile.do` 仍返回 JSON，但 `data` 改为 `/DocSystem/Manage/streamLogFile.do?key=<urlencoded key>`
- 新增 `streamLogFile.do`：session + 管理员校验 → `resolveLogFile(key)`（**白名单**，不接受任意路径）→ `text/plain` + `Content-Disposition: attachment` + `Cache-Control: no-cache` + `Content-Length`（<2GB 时）→ 8KB 缓冲顺序回写字节流
- **不写调试日志**（与 `getLogContent.do` 同理）：它服务的就是这份日志，`Log.infoHead` 的标记行会落进本次下载到的文件里；去掉后「下载内容 == 磁盘文件」严格成立（长度 + SHA-256 可比对）
- 前端 `main.js` / `logViewer.js` 均无需修改（仍是「ajax 拿 URL → `window.location.href`」）

### 6.4 实施中踩到的两个坑

1. **`MyInterceptor` 的地址白名单是「包含匹配」**（`uri.contains(s)`，`src/spring-mvc.xml:70-77` 注册，`path="/**"`）。白名单里有 `Manage/getSystemLog`，所以 `getSystemLogList.do` 匿名访问能进 handler（返回 JSON `NOT_LOGIN`）；而新接口 `exportSystemLogList.do` **不在白名单**，且 `fetch` 不带 `X-Requested-With` → 非 ajax 且未登录 → `sendRedirect("tologin.do?option=reload")` → 该地址无映射 → **404 HTML**（前端就会把 HTML 当文件下载）。
   处理：前端 fetch 补 `X-Requested-With: XMLHttpRequest`（jQuery ajax 本来就会带，这也是页面里其它请求能拿到 JSON 错误的原因），保持与既有接口一致的行为，不动白名单。
2. **`streamLogFile.do` 原本 `Log.infoHead(...)` → 写进自己正在下载的那份日志**，导致下载内容比磁盘文件多一行（且顺序上先写日志后算长度，所以长度/哈希仍自洽，但内容被污染）。已按 `getLogContent.do` 的既有约定去掉该接口的全部调试日志写入。
