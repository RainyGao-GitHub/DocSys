# 用户批量导入方案

> 目标：客户用**自己的用户名单**（CSV / Excel）一次性创建大量用户，替代逐个「新增用户」。
> 状态：**方案待裁定**（2026-10-06 调研完成，未开工）
> 关键约束：客户名单的**列名不固定**（中英混用、顺序不定、多出无关列）→ 必须做**列名别名兼容**。

## 1. 结论速览（推荐方案）

```
[用户管理] 「批量导入」→ 选择 CSV/XLS/XLSX → 服务端解析 + 列名别名映射
   → 逐行复用现有校验与创建逻辑（userCheck / checkSystemUsersCount / userService.addUser）
   → 返回逐行结果（成功/跳过/失败 + 明细）→ 前端结果面板 + 刷新列表 + 记一条系统日志
```

- **解析在服务端**（`ManageController` 新增 `importUserList.do`）：客户端 MD5、密码、长度、唯一性、越权、证书用户数上限等规则**只在服务端实现一套**，避免与 `addUser` 漂移。
- **列名兼容靠「归一化 + 别名表 + 忽略未知列」**（见 §3.2），不要求客户改文件。
- **逐行创建、逐行报告**（不整体回滚），与既有「系统参数导入」(`SysConfig/import.do` 返回 `{success,failed,total,errors[]}`) 的语义一致。

## 2. 现状与先例（已核对源码/实测）

### 2.1 已有「导出用户」（重要：不能直接当模板）

- 入口：用户管理页「导出」→ `main.js exportUserList()` → `POST /DocSystem/Bussiness/exportUserList.do`
  → 写 `<docSysIniPath>/backup/userList.csv` → 返回 `Doc/downloadDoc.do?...` 链接 → `window.location.href` 下载
  （**该接口在 websocket 仓库** `src/com/DocSystem/websocket/BussinessController.java:5285`）
- dev 实测导出内容（前 300 字节）：

```
serialVersionUID,id,name,pwd,type,role,realName,nickName,img,email,emailValid,tel,telValid,lastLoginTime,lastLoginIp,lastLoginCity,createType,createTime,intro,networkSettings,docSysType,isSalesServer,
4543706613855037637,1,Admin\t,e3afed0047b08059d0fada10f400c1e5\t,2,0,,,,652055239@qq.com\t,1,137774...
```

  该文件的 5 个特征（`LuceneUtil2.buildCsvTitleStrForObject/buildCsvStrForObject` 反射生成）：

  | 特征 | 说明 |
  | --- | --- |
  | 列头 = `User` **反射全字段** | 含 `serialVersionUID`、`docSysType`、`isSalesServer` 等；且**尾随逗号**（列数比列头多 1 个空列） |
  | **字符串值尾随 `\t`** | `Admin\t` / `pwd\t` —— 非标准 CSV |
  | **无引号、无转义** | 值里含 `,` 就会错列 |
  | **含 `pwd`（密码哈希）** | 安全上不理想 |
  | 列头是英文字段名 | 对客户不友好 |

  ⇒ **不能作为对外的导入模板**；但解析器应当**容忍它**（trim `\t`、忽略未知列、忽略尾随空列），做到「导出的文件能原样回灌」。

### 2.2 用户创建链路（要复用的规则）

| 位置 | 事实 |
| --- | --- |
| `ManageController.addUser` | 要求 `login_user.type >= 1`；`type > login_user.type` → **越权拒绝**；`checkSystemUsersCount` + `userCheck(user,true,true,rt)`；`createType = UserCreateType_ByAdmin`；写 `createTime`；成功/失败各记一条系统日志 |
| `BaseController.userCheck(user, emailCheckEn, telCheckEn, rt)` | 账号非空 + 不重复（`isUserNameUsed`）；手机/邮箱**格式 + 唯一性**（`isTelUsed/isEmailUsed`，**LDAP 创建的用户不算占用**）；命中则 `telValid/emailValid = 1` |
| `BaseController.checkSystemUsersCount` → `BusinessChannel.systemLicenseInfoCheck` | 证书用户数上限：`geAllUsers().size() > usersInfoCount` → 报「用户数量已达到上限…」 |
| 密码 | 前端 `addUser.js` 提交 **MD5(明文)**，服务端**原样入库**（服务端也有 `MD5.md5` 可用）；`resetPwd` 仅**超管**可用且受同/高级别保护 |
| 删除 | `delUser` 为**硬删除**，并清理 `DocAuth/ReposAuth/GroupMember` → 被删用户的**账号可再次导入**（不会撞唯一性） |

### 2.3 用户表结构（`BaseController:18295` 建表语句）

```
NAME VARCHAR(40)   PWD VARCHAR(40) NOT NULL   TYPE INT NOT NULL DEFAULT 0
ROLE INT           REAL_NAME VARCHAR(50)      NICK_NAME VARCHAR(50)
EMAIL VARCHAR(50)  TEL VARCHAR(20)            INTRO VARCHAR(10000)
CREATE_TYPE INT NOT NULL DEFAULT 0            CREATE_TIME VARCHAR(50)
```

两个硬结论：
1. **`PWD` 是 NOT NULL** ⇒ 导入必须为每行准备密码（§3.4 必须裁定）。
2. **字段有长度上限** ⇒ 导入前必须做长度校验，否则 MySQL 严格模式报错、非严格模式**静默截断**。

## 3. 方案设计

### 3.1 支持格式与解析

| 格式 | 处理 |
| --- | --- |
| `.csv` | 自研轻量解析器：分隔符启发（`,` 优先，兼容 `;` / `\t`）、支持双引号包裹与 `""` 转义、**值 trim（含 `\t`，兼容旧导出）**、忽略全空行；编码：**BOM 优先** → 严格 UTF-8 试解 → 失败回退 cpdetector/GBK |
| `.xls` / `.xlsx` / `.et` | POI `WorkbookFactory.create(InputStream)`（`.et` 先按魔数判定）；取**第一个 sheet**；用 `DataFormatter` 取值（避免数字/日期变形）；跳过全空行 |
| 其它 | 报「不支持的文件格式，请使用 CSV 或 Excel」 |

上限（可裁定）：文件 ≤ 5 MB、数据行 ≤ 5000 → 超限**直接报错**，不做流式/分批（内存与耗时可控）。

### 3.2 列名兼容（本需求的核心）

**（1）归一化**：去 BOM/首尾空白 → 转小写 → 去掉空格、`_`、`-`、`.`、`（）()`。

**（2）别名表（初版，可扩充）**：

| 目标字段 | 别名（归一化后） |
| --- | --- |
| `name`（**必填**） | `name` `username` `loginname` `login` `account` `useraccount` `账号` `帐号` `用户名` `登录名` `登录账号` `用户` |
| `pwd` | `pwd` `password` `passwd` `密码` `登录密码` `初始密码` |
| `realName` | `realname` `姓名` `名字` `真实姓名` `真实名` |
| `nickName` | `nickname` `昵称` `显示名` `显示名称` |
| `tel` | `tel` `mobile` `phone` `telephone` `mobilephone` `手机` `手机号` `手机号码` `电话` |
| `email` | `email` `mail` `mailbox` `邮箱` `电子邮箱` `邮件` `电子邮件` |
| `type` | `type` `role` `usertype` `用户类型` `角色` `权限` `用户级别` `级别` |

**（3）匹配规则**：
- 精确命中别名 → 采用；**未识别的列一律忽略**（不报错，兼容客户文件里的工号/部门/备注等列）。
- 同一字段命中多列 → 取**第一个非空**值（并可在结果里给出提醒）。
- **找不到「账号」列 → 直接报错**，并在错误里列出期望列名（最有用的一条提示）。
- **首行必须是列名**（不支持无表头）。若确需无表头，另开「按固定列序解析」开关（默认关，见 D2）。

**（4）值规范化**：
- 全部 `trim`；去掉首尾成对引号。
- `type` 文本 → 数字：空/`普通用户`/`用户`/`user`/`0` → `0`；`管理员`/`admin`/`1` → `1`；`超级管理员`/`超管`/`superadmin`/`2` → `2`；其它 → **该行报错**（不猜）。
- `tel` 去掉空格与 `-`；`email` 去空格。
- 空字符串 → 视为「未提供」（不写近 DB 的空串，除 `email` 库里有 `DEFAULT ''` 语义可写 `''`）。

### 3.3 逐行校验与创建（复用，不新造规则）

按行执行（顺序即报错优先级）：

1. **长度校验**：`name ≤ 40`、`pwd(明文) ≤ 40`、`realName ≤ 50`、`nickName ≤ 50`、`email ≤ 50`、`tel ≤ 20` → 超长该行失败（避免 DB 报错/静默截断）。
2. **账号非空** + `isUserNameUsed` → 已存在按 D3 处理（跳过/更新）。
3. **越权**：`type > login_user.type` → 该行失败（与 `addUser` 一致）。
4. **`checkSystemUsersCount`**：超限则该行及**其余所有行**失败（报「用户数量已达到上限，请购买商业版证书」）。
5. **`userCheck(user, true, true, rt)`**：手机/邮箱格式与唯一性（含 `telValid/emailValid` 置位）。
6. **创建**：`pwd = MD5.md5(明文)`、`createType = UserCreateType_ByAdmin`、`createTime = now`、`userService.addUser(user)`。

失败行**不写库、不中断**其它行；全部结果汇总返回（含 Excel/CSV 的**行号**，便于客户定位）。

### 3.4 密码策略（`PWD NOT NULL`，必须定）

| 选项 | 说明 | 评价 |
| --- | --- | --- |
| A 文件里有密码列就用它 | 服务端 `MD5.md5(明文)` 入库 | 推荐组合 |
| B 无密码列 → 默认密码 = **账号本身** | 客户最熟悉（导入即可用账号=密码登录），也便于批量口头通知 | **推荐** |
| C 无密码列 → 固定值（如 `123456`） | 简单但弱口令风险 | 不推荐 |
| D 无密码列 → 随机密码 + 结果文件输出 | 最安全，但客户要保存结果并逐个通知 | 可选 |
| E 系统参数里加「默认初始密码」配置 | 需遵守 `devDocs/参数存储策略与参数清单.md`（业务参数字典位置、不得只改 classes 等） | 若客户要改默认值才做 |

> 注：**LDAP 用户**登录走 LDAP 校验，本地 `pwd` 只是占位——导入 LDAP 名单时用同一套密码策略即可（不影响登录）。

### 3.5 接口与返回

- `POST /DocSystem/Manage/importUserList.do`，`multipart/form-data`，字段 `uploadFile`（文件）+ `existPolicy`（skip/update）+ `pwdPolicy`（file/name/fixed…）
- 权限：与 `addUser` 一致（`login_user.type >= 1`），未登录/无权限返回 JSON 错误
- 返回（对齐系统参数导入的形状）：

```json
{"data":{"total":100,"success":95,"skipped":3,"failed":2,
         "errors":[{"row":7,"name":"zhangsan","reason":"手机格式错误！"}],
         "note":"..."},"status":"ok"}
```

## 7. 风险与「本次不做」

**风险**
- **编码误判**：GBK/UTF-8 混淆 → BOM 优先 + 严格 UTF-8 试解 + cpdetector/GBK 回退；无法解码时明确报错（不猜）。
- **字段超长**：已在导入前校验（§3.3-1），避免 MySQL 严格模式报错或静默截断。
- **大文件**：行数/大小上限兜底（D7）。
- **旧导出兼容**：`\t` 与尾随空列已在解析里处理（§3.1/§3.2）。
- **并发/重复提交**：前端按钮禁用 + 服务端按账号查重（第二次导入会走「已存在」策略）。

**本次不做**
- 用户组/仓库权限的批量授予；批量修改/停用用户。
- 「无表头按列序解析」、字段级映射向导（选列→字段的图形映射）。
- 超大数据量（数万行）的异步分批导入与进度条。
- 顺手改造旧「导出用户」的格式（见 D11，另立任务）。

## 8. 实施记录

### 8.1 M1 解析与列名映射 ✅ 2026-10-06

新增 `src/com/DocSystem/common/UserListImporter.java`（主仓库，纯静态、无 Spring 依赖，便于探针直调）：

| 能力 | 实现要点 |
| --- | --- |
| 格式分发 | 按扩展名：`csv/txt` → CSV；`xls/xlsx/et/ett` → POI `WorkbookFactory`（`.et` 按魔数判 xls 还是 xlsx） |
| CSV 编码 | BOM（UTF-8/UTF-16）优先 → **严格 UTF-8 试解**（`CharsetDecoder` REPORT）→ 回退 GBK |
| CSV 切分 | 标准状态机：双引号包裹、`""` 转义、引号内换行；分隔符启发（`,` `;` `\t` 取首行最多者）；**字段值 trim（含 `\t`）** |
| Excel | 第一个 sheet；`DataFormatter` 取值；`13800000000.0` → 还原为整数字符串；全空行跳过 |
| 列名映射 | `normalizeHeader`（去 BOM/空白/`_-./（）()` 等）+ 别名表（`ALIAS_PRIMARY` 主 / `ALIAS_SECONDARY` 次，如「工号」只在没有「用户名」时才用）+ **未识别列忽略** |
| 值规范化 | 角色文本→数字（0/1/2；非法返回 -1 由调用方报错）；手机去空格/横线/`+86`/`86` 前缀 |
| 上限与长度 | `MAX_FILE_SIZE=5MB`、`MAX_ROWS=5000`、`MAX_DETAIL_ROWS=500`；长度常量与 user 表 DDL 一致 + `checkFieldLengths()` |
