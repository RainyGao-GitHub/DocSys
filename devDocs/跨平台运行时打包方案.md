# 跨平台运行时打包方案（2.02.88）

> 建立于 2026-10-11。**目标**：落实 2.02.88「**JRE 改用 GraalVM**」在**各目标平台**的运行时选型与校验口径。
> 相关：工作卡 `DevAgentControl/CURRENT_STATE_JDK升级选型.md`；选型/迁移计划 `src/com/DocSystem/websocket/office/docs/GraalJS替代Nashorn评估计划.md`（§6.1/§6.2）。
> **本版（2.02.88）允许放弃对部分平台的支持**（用户 2026-10-11 裁定）。

## 1. 背景

产品默认 JS 引擎已翻转为 **`graaljs`**（阶段 1，2026-10-07），因此**运行时必须能提供 GraalJS**：要么运行在 **GraalVM**（自带 GraalJS），要么 classpath 上有 GraalJS 的 jar。
2.02.88 把随产品的 `tomcat\java\jre` 换成 **GraalVM CE for Java 8**。
难点：**GraalVM CE 的 java8 发行版平台覆盖很窄**，导致部分平台没有可用的 GraalVM java8。

## 2. 事实：GraalVM CE for Java 8 的平台覆盖（已核实）

| 平台 | java8 发行版 | 备注 |
|---|---|---|
| Linux x86_64 (amd64) | ✅ | 一直有；**最后一个 java8 版 = 21.3.1** |
| Windows x86_64 (amd64) | ✅ | 同上 |
| **macOS x86_64** | ⚠️ **仅到 21.0.0.2** | 自 2021-04 CPU 起不再提供；**21.2.0 已无 darwin 包** |
| Linux aarch64 / macOS aarch64 | ❌ **从未有过** | java8 无 aarch64；首个 darwin-aarch64 是 22.1.0（仅 JDK 11/17）|
| Windows aarch64 | ❌ | 从未有过 |
| 鸿蒙 HarmonyOS | ❌ | 无 JVM（运行时是 ArkCompiler/ArkTS），传统 Tomcat 无受支持路径 |

来源：官方 `graalvm/graalvm-ce-builds` 发布资产（2026-10-11 核对 vm-21.2.0 / vm-21.0.0.2）。

## 3. 2.02.88 目标平台 × 运行时

## 4. 运行时如何被产品消费

- 落点：替换 `tomcat\java\jre`（4 个启动脚本 `docsys_start.bat` / `docsys_restart.bat` / `docsys_start_hidden.bat` 等把 `JAVA_HOME`/`JRE_HOME` 指向它）。
- 裁剪：按现有规则从 GraalVM 发行版裁剪出随产品分发的 `jre`（阶段 1 记录为"复制 `jre\*`，354 文件 / 471.9 MB，另补 `release` 与许可声明"）。
- **许可义务**：分发 Oracle/GraalVM 的运行时不得删改其版权/商标声明 → 打包校验需检查 `LICENSE`/`NOTICE` 存在。

## 5. 风险与注意

1. **Mac 用旧引擎（21.0.0.2）**：office 编辑器的 GraalJS 路径是在 **21.2.0** 上验证的；21.0.0.2 早约 2 个次版本 → **必须在 21.0.0.2 上重跑复验**（本机可用 Windows 版 21.0.0.2 复验 JS 语义，因为引擎行为与 OS 无关）。
2. **classpath 的 GraalJS jar 版本错配**：`WebRoot/WEB-INF/lib` 内是 **21.2.0** 的 4 个 GraalJS jar（阶段 1 新增）。运行在 GraalVM 上时会被**运行时自带版本遮蔽**（计划风险 19）。Mac 上即"运行时 21.0.0 生效"。→ 需确认没有反过来的遮蔽/冲突。
3. **麒麟 x64**：仅需确认 glibc 版本足够 + 实机冒烟（同一 Linux x64 二进制）。
4. **Mac 需额外一次"Darwin 实机"冒烟**：引擎语义复验过不代表 Darwin 版 JDK/启动器没问题。

## 6. 复验/冒烟清单（每平台）

1. **13 项引擎冒烟**：`src/com/DocSystem/websocket/office/test/tools/run_cjscontext_engine_mode.ps1 -GraalVmHome <运行时目录>`（graaljs 腿期望 PASS=13 FAIL=0）。
2. **三端转换门**：`...\tools\run_js_path_engine_compare.ps1 -GraalVmHome <运行时目录>`（word/slide/cell 与 nashorn 基线比对，期望 identical-modulo-timestamps）。
3. **应用侧**：用该运行时启动 Tomcat → `/DocSystem/` HTTP 200 → Office 打开一次并保存成功（日志 `strError` 空）。
4. **进程核对**：确认 Tomcat 用的是新运行时（`java -version` 显示 GraalVM）。

## 8. 21.0.0.2 复验结果（2026-10-11，实测）

在本机用 **Windows 版 GraalVM CE java8 21.0.0.2**（OpenJDK 1.8.0_282，sha256 与官方一致）复验（引擎行为与 OS 无关，可代表 Mac 的引擎语义）：

| 检查 | GraalVM **21.0.0.2** | GraalVM **21.2.0**（基线）| **stock JDK8 + 21.2.0 jar** |
|---|---|---|---|
| 13 项引擎冒烟（graaljs 腿）| ✅ PASS=13 | ✅ PASS=13 | ✅ PASS=13 |
| 三端门 word | ✅ IDENTICAL-MODULO-TIMESTAMPS | ✅ 同左 | ✅ 同左 |
| 三端门 slide | ✅ IDENTICAL-MODULO-TIMESTAMPS | ✅ 同左 | ✅ 同左 |
| 三端门 **cell(xlsx)** | ❌ **内容不同=5**（sharedStrings/styles/sheet1-3；产物 8626B）| 内容不同=**0**（仅 1 个单侧文件 `sheet1.xml.rels`；8440B）| 内容不同=**0**（8441B）✅ |
| JS 执行耗时（同门内 `run` 步）| — | ~1.3 s（PoC）| **~3.0–3.4 s** |

**结论**：
1. **GraalJS 21.0.0 与 21.2.0 在 xlsx 上行为不同**（21.0.0 多出 style/string 条目）；**21.2.0 才是与旧 nashorn 基线一致的那一侧**。故 **Mac 若用 GraalVM 21.0.0.2，xlsx 产物会与其它平台不一致**（风险）。
2. **stock JDK8 + classpath 21.2.0 GraalJS jar 完全复现 21.2.0 行为**（cell 内容不同=0）→ **引擎与 Win/Linux/麒麟 一致**；代价是解释执行较慢（~3.2 s vs GraalVM ~1.3 s，但仍比 nashorn ~21 s 快约 6×）。
3. 因此 Mac 有两种候选：**(A) GraalVM 21.0.0.2**（快、但 xlsx 行为不一致）；**(B) stock JDK8 + 21.2.0 jar**（行为一致、略慢）。
4. 附加红利：路线 B **不依赖 GraalVM 的平台覆盖** → 理论上可把 **Apple Silicon / ARM64 也支持回来**（原生 JDK8 即可）。

## 9. 裁定（2026-10-11）：各平台运行时

| 平台 | 运行时 | GraalJS 版本 | 备注 |
|---|---|---|---|
| Windows x64 | GraalVM CE **21.2.0** | 21.2.0（运行时内置）| 已复验 |
| Linux x64 / 麒麟 x64 | GraalVM CE **21.2.0** | 21.2.0 | 已复验 |
| **macOS Intel** | **stock JDK8**（建议 Eclipse Temurin 8 x64）+ 随包 `WEB-INF/lib` 的 **21.2.0** GraalJS jar | **21.2.0** | 解释执行 ~3.2 s；**引擎与其它平台一致** |

⇒ **全平台统一 GraalJS 21.2.0**（JS 行为一致）；差异只在 JVM（GraalVM vs stock）→ **只有性能差异**。
⇒ 路线 B 不依赖 GraalVM 平台覆盖 ⇒ **Apple Silicon / ARM64 亦可支持**（原生 JDK8，**待用户裁定**）。
⇒ **不采用** GraalVM java8 **21.0.0.2** —— 其 GraalJS 21.0.0 在 xlsx(cell) 上与 21.2.0 行为不一致（实测已证）。
⇒ Mac 上 classpath 与运行时**同版本（21.2.0）** ⇒ 无 §5-2 的遮蔽错配问题。
