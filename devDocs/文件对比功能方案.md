# 文件对比功能方案

建立：2026-10-28（调研+方案成文，未开工）。来源 issue：[I54IJU【NewFeature】文本文件对比功能](https://gitee.com/RainyGao/DocSys/issues/I54IJU)（2022-04-25，待办；参考的 CSDN 文章是纯手写逐字符比对，仅示意、非硬约束）。
状态：**待用户裁定（§9）后开工**。工作卡：`DevAgentControl/CURRENT_STATE_文件对比功能.md`。

---

## 1. 需求与场景

| # | 场景 | 入口设想 |
| --- | --- | --- |
| 1 | 选**两个文件**对比 | 文件列表/目录树右键两步式选文件 |
| 2 | 文件**两个历史版本**对比（或某版本 vs 当前 / vs 上一版） | 历史版本列表页勾选两个版本 |
| 3 | **AI 对比技能**结果呈现 | agent 调 `compare_docs` 工具 → 回答附对比链接（参照写操作产物链接）→ 点击打开对比窗口 |

**多方对比（三方及以上）**：建议本期不做（§9-B）。理由：DocSys 没有 git 式合并冲突流（无 base 版本参与裁决的产品场景），三方对比的价值在冲突合并；单纯"三个文件对齐看差异"（Beyond Compare 3-way）属小众，CM5 merge 的 `origLeft+origRight+value` 三窗格将来要做也支持，架构上不封死。

## 2. 现状测绘（2026-10-28，实施时勿重复找）

### 2.1 取数：零后端新增（场景 1/2）

- **`DocController.getDocContent.do`**（`DocController.java:3892`）：参数已含 `commitId / historyType /
  needDeletedEntry / shareId`；RealDoc 路径（:3982）文本直读（`readRealDocContentEx`），
  **Office/PDF 走既有文本提取**（`checkAndGenerateOfficeContentEx` → content.md），带 commitId 时走
  `getRealDocHistoryContent`（:4038，先从版本库 checkout 历史文件再读）。
- **前端现成封装** `getDocText/getDocTextBasic`（`DocSys.js:~680`）：POST `getDocContent.do`，返回
  `ok+文本`；历史版本（`docInfo.isHistory==1`）跳过临时保存内容合并。分享链（shareId/authCode）同接口支持。
- **历史列表数据**：`getDocHistory.do`（:5401）+ 前端 `DocHistory.js`（行按钮 详情/下载/恢复/回退/删除，
  行内 `#commitId{i}` 取版本号）。

### 2.2 对话框与打开模式

- artDialog + iframe：`project.js:2092`（showDocHistory 打开 `historyLogsForArt.html` 的完整样板，
  含 `window.artDialogList[dialogId]` + `data` 传参、big/resize、sandbox 白名单）。
- 独立窗口：`openDoc`（`DocSys.js:2569` `window.open(.../ace.html?...)`）。
- ⚠️ URL 传参陷阱：多选 @ 的先例（2026-09-24）——中文/长路径会撞 Tomcat 8KB 请求行，**走
  artDialog data / sessionStorage，不塞 URL**。

### 2.3 AI 产物链接（场景 3 现状）

- `AgentProductLink`：`PRODUCT_TOOLS` 白名单 → `Product{vid,path,name,docId,action}` → 回答末尾
  追加机器标记（`appendFooter`，幂等）→ 前端 `extractProducts/renderProductLinks`（agent/index.html）
  渲染链接、`openProductInParent` 同源父窗口 `openDoc` 回退新开窗口。
- 「对比」目前只是提示词级操作（`AgentFocusSupport.OPERATIONS.put("compare", ...)`），无专用工具，
  模型用 get_doc 读文本自行比对。

### 2.4 文件列表选择能力

- 目录树（zTree）单选 + **Shift 同级多选**（`project.js:2625`，用于批量 @）；无 Ctrl 通用多选 UI。
- 右键菜单按 tree/docPreview 两套挂载（`project.js:6411/6415` 附近）。

### 2.5 已有编辑器资产

- ACE 已自托管（`WebRoot/web/static/ace-builds/src-min/`，文本/代码编辑用）。**ACE 无官方 diff 视图**
  （只有 diff 语法高亮），自研双栏对齐成本高于直接用 CM5 merge。

## 3. 前端方案候选对比（调研 2026-10-28）

| 候选 | 免构建引入 | diff 视图能力 | 三方 | 维护 | 体积 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| **CodeMirror 5 + merge addon**（+diff_match_patch，外部依赖） | ✅ 纯 script/css（`addon/merge/merge.js`+`merge.css`+`lib/*`+按需 mode） | ✅ 双栏+行内（viewToggle 需自实现切换）、折叠相同段（collapseIdentical）、对齐线（connect:'align'）、块复制按钮（revertButtons）、忽略空白（ignoreWhitespace） | ✅ origLeft+origRight+value | ⚠️ 维护模式（仅关键修复，成熟稳定 5.65.x） | 小（核心+merge+dmp+常用 mode ≈ 1MB 内） | **推荐** |
| CodeMirror 6 官方 `@codemirror/merge` | ❌ **仅 ESM/CJS，必须 bundler**（官方文档明示） | ✅ 现代、能力同级 | ❌（2 路） | ✅ 活跃 | 小 | 否决：与本项目无构建链冲突，引入打包链是架构级变更 |
| Monaco DiffEditor | ⚠️ AMD loader 可免构建，但 **AMD 已官方废弃**（未来版本移除）；worker 配置繁琐 | ✅ 最强（VS Code 级） | ❌ | ✅ | 大（min/vs MB 级） | 备选：若用户要"VS Code 级"且接受重量/锁旧版 |
| Mergely（jQuery 插件） | ✅ | 基本双栏 | ❌ | ❌ 基本停更 | 小 | 否决：维护风险、能力弱于 CM5 merge |
| diff2html + jsdiff（只读渲染） | ✅ | 只读 unified/双栏高亮，无对齐/折叠交互/编辑 | ❌ | ✅ | 小 | 否决为主方案（无编辑器对齐体验）；可作为将来"导出 diff 报告"补充 |

**推荐理由归纳**：DocSys 前端是"静态 HTML + 全局脚本 + artDialog iframe、无任何 JS 构建链"的架构，
**免构建是硬约束**；在此约束下 CM5 merge 是唯一同时满足功能面与维护度的成熟方案；CM5 虽处维护模式，
但作为内网文档产品的对比视图足够（若将来引入构建链，CM6 merge 概念同构可平移）。

**落地形态**：vendor 到 `WebRoot/web/static/CodeMirror5/`（固定 5.65.x 版本，含 LICENSE；
`static/diff-match-patch/`（Apache-2.0，含 NOTICE））；**不依赖 CDN**（内网）。
页面引用统一 `?v=20261028` 起始（project.js 先例纪律）。

## 4. 总体架构

```
入口层（三处）                 展示层                     数据层
─────────────                ──────────────────        ─────────────────
① 右键两步选文件   ──┐
② 历史列表勾选两版 ──┼──► compareForArt.html          ──► getDocContent.do（现有）
③ AI compare_docs ──┘      （artDialog iframe / 新窗口）    · 文本直读
                            · CodeMirror 5 MergeView        · Office/PDF → 提取文本
                            · 双栏默认 + 行内切换            · commitId/historyType 历史版本
                            · 折叠相同段（默认开）           · shareId/authCode 分享链（P2）
                            · 语法高亮（按后缀选 mode）
                            · 差异统计（+N/-M、变更块数）
                            · 只读（编辑/revert 后续版本再议）
```

**对比参数模型**（两侧对称）：

```js
compareRef = {
  vid, path, name, docType,          // 定位文件
  commitId?, historyType?,           // 可选：历史版本（场景2）
  shareId?, authCode?                // 可选：分享链（P2）
}
// 打开窗口 = { left: compareRef, right: compareRef }
```

传递：artDialog 模式走 `data`（照 showDocHistory 样板）；agent 页/独立窗口走 sessionStorage（同源），
URL 只带最小参数（窗口标题用）。**两侧可以是不同仓库的文件**（各自带 vid）。

## 5. 场景设计

### 5.1 场景 1：选两个文件对比（M1）

- 右键菜单（目录树 + 文件列表两处）新增「**设为对比文件**」；选中第一个后 toast 提示
  「已选择 X，请再右键要对比的另一文件 → 与之对比」；第二个文件右键出现「**与 X 对比**」。
- 两步式而非先做文件选择器：复用现有多选心智、零新 UI 组件、天然支持跨目录跨仓库；
  独立"对比选择器"面板留作后续增强（不进本期）。
- 校验：两侧 docType 相同（RealDoc）；文本/代码直接比；Office/PDF 提示「按提取文本对比」；
  其余二进制（图片/压缩包）提示不支持。

### 5.2 场景 2：历史版本对比（M2）

- `historyLogsForArt.html`（DocHistory.js）：
  - 每行加复选框，选中 **恰好两个** 时顶部「对比选中版本」可用（旧→新 为 左→右）；
  - 行按钮新增「**与当前对比**」（该 commitId vs 工作区当前内容）；
  - （可选便宜项）「与上一版对比」= 该版本 vs 列表中它的上一条（同一文件的历史列表天然有序）。
- historyType 范围：0（版本管理）为主，2/3（本地/异地备份）复用同一 commitId 机制顺带验证；
  4（回收站）不进对比。仓库级历史（docId 为空的目录级 commit 列表）不提供。

### 5.3 场景 3：AI 对比技能（M3）

- 新增 agent 工具 `compare_docs`（DocSysToolFactory 注册）：
  - 参数：`vidA/pathA/nameA[, commitIdA?]` + `vidB/pathB/nameB[, commitIdB?]`（或结构化 docA/docB 对象，
    实施时按工具 schema 惯例定）。
  - 执行：后端复用 getDocContent 的读取路径（Service 层提取公共方法）取两侧文本 →
    行级 diff 统计（变更块数、+N/-M、首 K 处差异摘录）→ **ToolResult.data = Compare 产物**
    （`AgentProductLink` 扩展：`action:'compare'`，Product 携带两侧 ref）。
  - 给模型的文本结果：差异摘要（让"对比"操作回答有真凭据，而不是模型肉眼比两段长文本）。
- 前端：`renderProductLinks` 识别 compare 产物 → 渲染「XX ⟷ YY 对比」链接 →
  `openCompareWindow(pair)`（同源父窗口优先 / 新窗口回退，照 openProductInParent 模式）。
- 兼容：marker 行结构向后兼容（新增 action 值，旧数据不受影响）；旧版前端遇到未知 action 的行为
  实施时核验（不渲染或降级为纯文本，不可报错）。

### 5.4 对比窗口本体（M1 交付，M4 打磨）

- `compareForArt.html` / `_en.html`（artDialog big 全屏 + resize，照 historyLogsForArt 样板）。
- MergeView 配置基线：`collapseIdentical: {margin:3}`（默认折叠相同段，可切换）、
  `connect:'align'`、`revertButtons:false`（只读）、`allowEditingOriginals:false`、
  `readOnly:true`、按后缀映射 mode（复用 `getFileShowMode` 的映射思路，缺省纯文本）。
- 工具条：双栏/行内切换、折叠相同段开关、忽略空白开关、差异统计（+N/-M · K 处变更块）、
  左右标题（文件名@版本 or 文件名@当前）。
- 大文件保护：单侧文本 > 2MB（默认阈值，可配）拒绝并提示；diff 在前端 dmp 计算（O(nd)）。

## 7. 风险与注意

- **CM5 维护模式**：接受度由用户裁定（§9-A）；锁 5.65.x 固定版本 vendor，风险可控。
- **merge.js 大文件性能**：dmp 为 O(nd)，两段高度相似的大文本 OK，差异巨大的大文本会慢 → 大小上限 + 超限提示。
- **artDialog iframe 内 resize**：MergeView 需随窗口 resize 刷新（CodeMirror.css 100% 高度 + 手动刷新，实施处理）。
- **Office 对比是"提取文本"**：非原始格式（表格/样式不参与），窗口标题注明；无提取结果时提示。
- **静态缓存**：新库引用带 `?v=`；挂起卡 `CURRENT_STATE_前端静态资源缓存.md` 的全量治理不并入本任务。
- **英文页**：新页面双语；历史页/右键菜单文案走 `_Lang`。
- **权限**：全程走既有 `checkAndGetAccessInfo`（含分享链）；对比窗口在"分享页"场景的入口本期不做。

## 8. 测试要点（每阶段实测）

- M1：右键两步（同目录/跨目录/跨仓库/取消重选）；文本/代码语法高亮；Office 提取文本提示与展示；
  二进制拒绝；大文件拒绝；折叠/切换/统计；中英页。
- M2：两版本对比（左旧右新）；与当前对比；无版本管理仓库入口隐藏；备份历史（historyType 2/3）验证。
- M3：AI 执行对比 → 链接渲染 → 点击打开窗口参数正确；旧回答（无 marker）不受影响；权限不足的报错路径；
  compare 操作的回答质量（引用真实差异摘要）。
- 回归：project.js 改动处（右键菜单）+ DocHistory.js 改动处原有功能；agent 页产物链接原功能（new/modified）。

## 9. ★ 裁定（用户已裁定 2026-10-28）

- **A 前端库 = CodeMirror 5 merge addon**（+diff_match_patch）。
- **B 多方对比：本期只做两方**；三方后续需要时另立卡（CM5 merge 的 origLeft+origRight 结构不封死）。
- **C 本期对比窗口只读**（无编辑/合并按钮）。
- **D AI 工具返回「差异摘要 + 对比链接」**。
- **E 限制与 Office 策略**：单侧 >2MB 拒绝；二进制中**只支持 Office 文件**（其余不支持）。
  **Office 对比形态（用户 2026-10-28 新裁定）：不做提取文本比对，而是在对比窗口里并排打开两个
  Office 查看器**（借用对比窗口外壳；放弃 CM5 差异高亮）：
  - 实现：文本模式窗口里对 Office 文件渲染**两个 iframe 各加载 `office.html?<buildRequestParamStrForDoc>`**
    （该查看器已支持 commitId 历史版本——viewVDocHistory 先例）；PDF 同样并排预览。
  - 双 Office 实例的资源/兼容风险集中到 M4 实测验证；M1~M3 阶段 Office 对比先给"即将支持"提示。
  - 场景 3 的**差异摘要仍用提取文本计算**（摘要给模型看，呈现给用户看原格式并排）——两者互补。
- **F 分阶段确认**：M1 窗口+右键入口 → M2 历史对比 → M3 AI 工具与链接 → M4 **Office 并排模式**
  + 打磨回归；每阶段模型实测 → 用户验收。

## 10. 实施计划（裁定后生效）

- **M1**：vendor CM5+DMP → `compareForArt.html(±_en)` 窗口 → 右键两步入口 → dev 实测 → 用户验收。
