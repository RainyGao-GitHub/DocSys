# DocSys 参数配置：存储方式与工作机制说明

> **目的**：参数配置横跨「ini 文件 / `system_setting` 表 / `agent_config` 表」三套机制，改造时非常容易忘记某条配置到底存在哪、谁读它、什么时候生效。本文是**配置地图**，改任何配置相关功能前先看这里。
> **适用范围**：主仓库 `D:\Dev\DocSys`（不含 `websocket` / `office` 独立仓库）。
> **核对时间**：2026-10-04，依据当时源码；关键位置给了 `文件:行号`，若行号漂移以方法名为准。

---

## 0. 一句话总览

| # | 机制 | 定位 | 典型配置 |
| --- | --- | --- | --- |
| ① | **ini 配置文件**（`docSys.ini/docSysConfig.properties` + `WEB-INF/classes/docSysConfig.properties` 副本） | 老机制，仍在用：**启动期静态读取**的键、以及少数直接读文件的功能 | `language`、`ldapConfig`、`llmConfig`、`allowedNetworkConfig`、`systemCompressEncoding`、`tomcatPath`、`maxThreadCount`、`redisEn`… |
| ② | **`system_setting` 表** | 「系统级服务/功能」配置的权威源；name/value/remark 字符串表，value 可放 JSON | `mail.*`、`sms.*`、`ldap.servers`、「系统参数」页手工加的行 |
| ③ | **`agent_config` 表** | Agent 侧配置（scope + key） | `system_prompt_override/suffix`、`agent_tool_choice`、`agent_max_turns`、`agent_absolute_guarded_extra`、`llm_models` |
| ★ | **运行期镜像**（②③ → ①） | 有些配置「运行期只能从配置文件读」（如 `ldapConfig`/`llmConfig`），做法是**库为权威源 → 渲染成老格式串写回 ini + classes 副本 → 更新内存静态量**。好处：消费方零改动、保存即生效、启动时再用库覆盖一次 | LDAP设置、AI接入设置 |

**为什么不一刀切全迁到数据库**：`BaseFunction` 的静态块在容器就绪前就读 `ini`（②③都需要数据库，读不了）；而登录/集群等消费方读的是内存静态量，改造成本高、风险大。所以采用「库+镜像」的折中，**新增配置时按 §8 决策树选位置**。

## 1. ini 机制细节

### 1.1 两个副本，读法不同（最容易踩）

```java
// classes 副本（WEB-INF/classes/docSysConfig.properties）—— classloader 根
ReadProperties.read("docSysConfig.properties", "key")          // util/ReadProperties.java:26
// 任意绝对路径 —— 用来读 docSys.ini
ReadProperties.getValue(docSysIniPath + "docSysConfig.properties", "key")  // :32
```

- `docSysIniPath` = **webapps 目录** + `docSys.ini/`（`BaseFunction.java:348`），即 `.../tomcat/webapps/docSys.ini/`。
- `docSysWebPath` = 应用目录（`.../tomcat/webapps/DocSystem/`），classes 副本在 `docSysWebPath + "WEB-INF/classes/"`。
- 两副本可能不一致：**`setSystemInfo.do` 会同时写两份**（见 1.3），但手工只改 ini 时，那些走 `ReadProperties.read()`（classes）的键**不会变**。

### 1.2 启动期 vs 请求期

**启动期（`BaseFunction` 静态块，`BaseFunction.java:334-360`）——这些键只读一次，改完必须重启**：

| 顺序 | 调用 | 读取的键 | 读法 |
| --- | --- | --- | --- |
| 1 | `initSystemLanguage()` (`:404`) | `language` | ini |
| 2 | `initSystemLicenseInfo()` | 授权/许可 | — |
| 3 | `initOfficeLicenseInfo()` | office 许可 | — |
| 4 | `initLdapConfig()` (`:2456`) | `ldapConfig` | ini |
| 5 | `intSystemAllowedNetworkConfig()` (`:2467`) | `allowedNetworkConfig` | ini |
| 6 | `initLLMConfig()` (`:2497`) | `llmConfig` | ini |
| 7 | `initSystemCompressEncoding()` (`:2477`) | `systemCompressEncoding` | ini |
| 8 | `serverHost = getServerHost()` | `mxsdoc.conf` 的 `serverHost` | 文件 |
| 9 | `clusterServerUrl = getClusterServerUrl()` (`:5717`) | `serverUrl` | **classes**（注意：这一步走 classes，不是 ini） |

> 静态块本身**不读**邮件/短信配置——它们早已入库（②）。

**请求期（每次调用都重新读文件）**：

| 方法 | 键 | 读法 |
| --- | --- | --- |
| `getJavaHome()` `:5617`、`getTomcatPath()` `:5633`、`getOpenOfficePath()` `:5756` | `javaHome` / `tomcatPath` / `openOfficePath` | classes |
| `getLdapConfig()` `:5647` | `ldapConfig` | classes |
| `getAllowedNetworkConfig()` `:5658` | `allowedNetworkConfig` | classes |
| `getLLMConfig()` `:5669` | `llmConfig` | classes |
| `getMaxThreadCount()` `:5680`（缺省 1） | `maxThreadCount` | classes |
| `getRedisUrl()` `:5705`、`getRedisEn()` `:5728` | `redisUrl` / `redisEn` | classes |
| `getClusterServerUrl()` `:5717` | `serverUrl` | classes |

**结论**：运行期静态量由启动期读 ini 得到；页面/接口回显走 classes；因此**必须保持两份一致**，`setSystemInfo.do` 的写法就是为此。

### 1.3 `setSystemInfo.do` 的写法（`ManageController.java:1710` 起）

1. 参数**全部可空**，`null` = 「本字段不改」；全为 null → 直接报「没有参数改动」。
2. `classes/docSysConfig.properties` → **拷贝**到 `docSys.ini/docSysConfig.properties`（以 classes 为基线覆盖 ini）。
3. 对每个非 null 参数 `ReadProperties.setValue(ini 路径, key, value)`（**每个字段一次文件重写**）。
4. ini → **拷回** classes。
5. 立即生效几个运行期静态量：`applySystemLdapConfig` / `applySystemAllowedNetworkConfig` / `applySystemLLMConfig`、`initDocSysDataPath()`、`initRedis()`（返回 true → `restartClusterServer()`）；`logLevel`/`logFile`/`isOnlyOfficeUsed`/`officeEditorApi` 当场改内存。

> ⚠️ **两个坑**
> 1. **jQuery 会把 `undefined` 序列化成空串，而空串 ≠ 「不改」**（会把该配置清空）。所以各页**必须按页白名单只提交自己负责的字段** —— 已有 `postSystemInfo(fields, onDone)`（`main.js`）与各页 `XXX_FIELDS` 列表；新增页面时照抄。
> 2. `ReadProperties.setValue` 用 `Properties.store()` 重写整个文件：**注释会丢、键顺序会重排、值里的 `:`/`=` 会被转义**（如 `ldap\://`）。这是正常现象，读回时无需手工反转义。

### 1.4 参数名 ↔ ini 键名映射（有几处大小写/名字不一致）

| 页面字段/接口参数 | ini 键 |
| --- | --- |
| `tomcatPath` / `javaHome` / `openOfficePath` / `officeEditorApi` | 同名 |
| `defaultReposStorePath` | `defaultReposStorePath` |
| `systemLogStorePath` | **`SystemLogStorePath`**（首字母大写） |
| `indexDBStorePath` | **`DBStorePath`** |
| `agentSkillStorePath` | **`AgentSkillStorePath`**（空 = 清除，回落默认 `<仓库存储>/skills/`） |
| `salesDataStorePath` | **`SalesDataStorePath`** |
| `ldapConfig` / `allowedNetworkConfig` / `llmConfig` | 同名 |
| `maxThreadCount` | `maxThreadCount` |
| `redisEn` / `redisUrl` | 同名 |
| `clusterServerUrl` | **`serverUrl`** |
| `isOnlyOfficeUsed` | `isOnlyOfficeUsed` |
| （数据库设置页，独立接口） | `jdbc.properties` 的 `db.type/db.url/db.username/db.password` |

### 1.5 版本门禁

`ldapConfig` / `llmConfig` 非空且当前非企业版时，`setSystemInfo.do` 只会 `docSysErrorLog(...)`（把错误文案带在响应里）**但仍然写文件**；真正的门禁在运行期：`applySystemLdapConfig` / `applySystemLLMConfig` 里按 `docSysType == DocSys_Enterprise_Edition` 决定 `enabled`（`BaseFunction.java:2507` / `:2652` 附近）。新版页面（LDAP设置/AI接入设置）在**校验阶段**直接拦住非企业版保存启用项。

## 2. `system_setting` 表机制

### 2.1 表与访问层

```sql
CREATE TABLE IF NOT EXISTS system_setting (
  id, `name` VARCHAR(128) NOT NULL,   -- 点分命名空间，如 sms.provider
  value LONGTEXT, remark VARCHAR(1024),
  create_time VARCHAR(32), update_time VARCHAR(32),   -- 应用层写本地时间（SQLite 的 CURRENT_TIMESTAMP 是 UTC）
  UNIQUE KEY uk_system_setting_name (`name`)
)
```
- 建表：`service/SystemSettingInitializer.java`（MariaDB/SQLite 双方言 + 缺表检测 + 幂等），由 `docSysInit` 成功路径的钩子触发。
- 访问：`SystemSettingService`（接口）/`SystemSettingServiceImpl`：`getValue/getJson/countByPrefix/exists/getRemark/getAll/getTotal/set/setMany/seedIfAbsent/delete`。
- **单条值 60s TTL 缓存**（`CACHE_TTL_MS`），`set/seedIfAbsent/delete` 后 `invalidateCache()`；**读异常一律不外抛**（返回 null/0/空表，调用方走兜底）。
- **不并入** `DBTabNameMap`（那张表与 `ObjMemberListMap`/objType 强绑定，不能加表）。

### 2.2 三种使用模式

| 模式 | 说明 | 代表 |
| --- | --- | --- |
| **a. 表为唯一权威源** | 表内有该前缀的行就只认表；表内没有时用 `properties` 旧值兜底（**不写回**）；首次启用时用 `ensureSeeded()` **一次性**把旧值搬进表（幂等：只在「表内没有任何该前缀行」时执行；旧值也为空 → 不写任何行） | `mail.*`（旧值读 **classes 优先**）、`sms.*`（旧值读 **ini 优先**） |
| **b. DB JSON 权威 + ini 镜像** | 库里的结构化 JSON 是权威源；保存/启动时**渲染成老格式串**写 ini + classes，并更新内存静态量 | `ldap.servers` → `ldapConfig`；`agent_config.llm_models` → `llmConfig` |
| **c. 通用键值** | 「系统管理 → 系统参数」页（`SysConfigController`）直接增删改任意行，用于兜底/运维 | 任意 `xxx.yyy` 行 |

### 2.3 相关页面

| 页面 | 键前缀 | 保存接口 |
| --- | --- | --- |
| 邮件服务 | `mail.*`（`mail.enabled/provider/from/fromName/smtp/aliyun/tencent/http/options`） | `Manage/setSystemMailConfig.do` |
| 短信服务 | `sms.*`（`sms.enabled/provider/scenes/yunpian/aliyun/tencent/custom/options`） | `Manage/setSystemSmsConfig.do` |
| LDAP设置 | `ldap.servers`（JSON） | `Manage/setSystemLdapConfig.do` |
| 系统参数 | 任意 | `SysConfig/set.do` |

## 3. `agent_config` 表机制

```sql
CREATE TABLE IF NOT EXISTS agent_config (
  id, scope VARCHAR(32) NOT NULL DEFAULT 'global',  -- global / 仓库ID（预留）
  config_key VARCHAR(64) NOT NULL, config_value LONGTEXT,
  UNIQUE KEY uk_scope_key (scope, config_key), INDEX idx_scope (scope)
)
```
建表：`agent/config/DatabaseInitializer.java`（`REQUIRED_TABLES` 含 `agent_config`），由 `BaseController.triggerAgentInit()` 触发。

**键清单与消费方**：

| key | 用途 | 消费方 |
| --- | --- | --- |
| `system_prompt_override` / `system_prompt_suffix` | 系统提示词整体覆盖 / 追加段落（智能体设置 → 提示词管理） | Agent 提示词装配 |
| `agent_tool_choice` | `auto`（默认，带 tools+tool_choice）/ `none`（纯文本通道） | 工具调用链路 |
| `agent_max_turns` | 单轮工具调用次数预算（默认 25，钳制 5~50） | `ToolUseLoop.setMaxTurns` |
| `agent_absolute_guarded_extra` | 追加的绝对保护工具名（逗号分隔） | `PermissionConfig`/权限模式 |
| `llm_models` | **系统级 LLM 模型列表（JSON 数组）** | `AgentLlmConfigStore` → 渲染 `llmConfig` 镜像 → `BaseFunction.systemLLMConfig` |

访问：`AgentConfigService`（`get/set/list/getGlobal/setGlobal`，失败只记日志返回 null/false）。

## 4. 启动顺序（谁在什么时候覆盖谁）

```
Tomcat 启动
 └─ BaseFunction 静态块：读 ini → systemLdapConfig / systemLLMConfig / allowedNetworkConfig / language / compressEncoding …
     （此时数据库还没连，库里的配置用不上）
 └─ Spring 容器就绪 → docSysInit()（BaseController）
     ├─ triggerAgentInit()          // AgentInitService.initAfterDocSysReady()
     │    ├─ 1) 建表（幂等）
     │    ├─ 1.5) 拷默认技能到配置目录（不覆盖已存在）
     │    ├─ 1.8) ★ 用 agent_config.llm_models 覆盖运行期 LLM 配置（写 ini/classes 镜像 + 内存）
     │    └─ 2) LLM 配置同步（读内存，无网络阻塞）
     └─ triggerSystemSettingInit()  // 建 system_setting 表 + 各 store 的 ensureSeeded()/applyToRuntime()
          ├─ SystemSettingInitializer.init()
          ├─ SmsConfigStore.ensureSeeded()
          ├─ MailConfigStore.ensureSeeded()
          └─ LdapConfigStore.ensureSeeded() + applyToRuntime()   // ★ 用 ldap.servers 覆盖运行期
```
要点：**静态块先跑（读 ini）→ DB 就绪后由库覆盖**。所以「库里有值」时，手工改 ini 会在下次启动被覆盖（页面上应知会管理员）。

## 5. 运行期「谁读什么」（改造时最常查的一张表）

| 配置 | 权威源 | 保存后 | 运行期消费者 |
| --- | --- | --- | --- |
| LDAP 服务器列表 | `system_setting.ldap.servers` | 立即写 `ldapConfig` 镜像 + `BaseFunction.systemLdapConfig` | `BaseController.loginCheck` → `LDAPUtil.ldapLoginCheck`；集群一致性检查 `getLdapConfig()`；`getSystemInfo.do` 回显 |
| AI 模型列表 | `agent_config.llm_models` | 立即写 `llmConfig` 镜像 + `systemLLMConfig` | `getAiModelList.do`/`AIChat.do`/`/agent/models/list`/`LlmConfigSyncService` |
| 邮件 | `system_setting.mail.*` | 直接读库 | `MailSender`（保存即生效） |
| 短信 | `system_setting.sms.*` | 直接读库 | `SmsSender`（保存即生效） |
| 系统设置页各路径 | ini（+classes） | 写两份 + 部分立即改内存 | `BaseFunction` 各 getter（请求期读 classes） |
| 集群开关/地址 | ini（`redisEn`/`redisUrl`/`serverUrl`） | 写两份 + `initRedis()`（必要时 `restartClusterServer()`） | `BaseController.initRedis()` 等 |

| 数据库连接 | `jdbc.properties` | 写两份 | **需重启** |
| Agent 各键 | `agent_config` | 直接读库 | 见 §3 |

## 6. 集群与一致性

- 集群检查（`BaseController.clusterDeployCheckGlobal_ConfigCheck`）把 `DB_URL`、`ldapConfig`、`LLMConfig`、`OfficeEditor` 与 **Redis 里缓存的全局值**逐个比对，不一致就报「集群检测失败:配置不一致」。
- 其中最硬的一条是 **`DB_URL` 必须一致 ⇒ 各节点共用同一个数据库** ⇒ `system_setting` / `agent_config` **天然共享，无需额外同步**。
- 但 **ini/classes 是每个节点的本地文件**：节点 A 保存后只有 A 的镜像更新，其他节点要各自保存一次（或同步 `docSys.ini`）才会一致。这是**既有行为**，不是 DB 化引入的。
- 与仓库相关的设置走 Redis 同步（仓库锁等）；**全局配置走「库 + 本机镜像」**，两者别混。

## 7. 备份 / 导出 / 导入覆盖范围

- `BaseController.buildExtraDBTabList()` = `ExtraDBTabNameMap`（`{system_setting}`）+ `AgentDBTabNameMap`（agent 系列表）；SQL 导出、JSON 导出、JSON 导入都追加这些表（`DBExtraTabBackup`）。
- 因此 **②③ 两类存储里的数据都在备份里**；导出键名形如 `system_setting:[...]`（裸标识符，未加引号）。
- 导入语义：逐行 INSERT，单行冲突只跳过并记日志。

## 8. 决策树：新增一个配置项该放哪

1. 是 **Agent 功能**的配置（提示词/工具/轮数/权限/模型）？→ `agent_config`，`scope=global`，新增 `AgentConfigService.KEY_*` 常量。
2. 是 **系统级服务/功能**（邮件/短信/LDAP/…）且运行期能直接读库？→ `system_setting`，起一个点分前缀（`xxx.*`），走 `*ConfigStore` 模式（纯函数校验 + `ensureSeeded()` 幂等播种 + 保存即生效）。
3. 必须**在容器就绪前**就可用（被 `BaseFunction` 静态块读）或消费方只认某个 ini 键 / 只读老格式串？→ **库 JSON 为权威源 + 渲染成老格式串写 ini/classes 镜像 + 更新内存静态量**（照抄 `LdapConfigStore` / `AgentLlmConfigStore`）。
4. 需要**重启**才对某些组件生效（如数据库连接）？→ 仍写 `jdbc.properties` 一类，页面明确写「需重启」。

**新增配置的检查清单**：
- [ ] 选好存储（§8 决策树），键名进命名空间并写进本文档 §5
- [ ] 纯函数校验（与前端同口径），错误文案可直接展示
- [ ] 首次迁移幂等（只在「表内无该前缀行」时播种；旧值空 → 不写任何行）
- [ ] 保存后立即生效（写内存静态量 / 或直接读库）
- [ ] 若走镜像：**ini + classes 两份都写**，并考虑启动时「库覆盖 ini」
- [ ] 备份覆盖：表在 `ExtraDBTabNameMap`/`AgentDBTabNameMap` 里；若是 ini 键则说明「不在备份里」
- [ ] 前端：按页白名单提交；只读态 `disabled`；中英文案；模板改动做一次渲染自检
- [ ] 验证：离线探针（纯函数）+ 接口级 + 真实页面 E2E + 「不重启即生效」与「重启后仍生效」两条

## 9. 常见坑（都是实测踩过的）

1. **`undefined` ≠ "不改"**：jQuery 把 `undefined` 序列化成空串，`setSystemInfo.do` 只把 `null` 当「不改」→ 必须按页白名单提交。
2. **两份 properties 会不一致**：`ReadProperties.read` 读 classes、`getValue` 读 ini；只改一份就会出现「页面显示了新值但运行期还是旧值」。
3. **`Properties.store()` 重写整个文件**：丢注释、键顺序变化、`:`/`=` 被转义。
4. **fastjson 省略 `null` 字段**：接口回传里可能缺字段，前端一律 `|| ""` 兼容；`getSystemInfo.do` 的空 `ldapConfig` 也会整字段消失。
5. **`system_setting` 有 60s 单条缓存**：绕过 Service 直接写库会读到旧值（走 `set()` 会自动失效）。
6. **表内有值即只读表**：mail/sms 的「表优先」策略意味着升级后手改 properties 不再生效（页面上有静态说明）。
7. **库覆盖 ini**：`ldap.servers`/`llm_models` 有值后，手工改 ini 会在下次启动/保存被覆盖。
8. **空列表 ≠ 未配置的语义要写清**：LDAP 清空 = 关闭 LDAP 登录；LLM 清空 = AI 未配置。两者都渲染成空串。
9. **模板里的帮助文案不能出现 `{{`**（会被当变量求值渲染成空白）。
10. **服务端返回的文案是中文**：英文页里这些动态文案仍是中文（彻底 i18n 需返回「文案码 + 参数」）。
11. **前端模板有内存缓存**（`$Func.loadModule` 的 `$Modules`）：改 `.html` 后必须整页重载才看得到，还要绕浏览器缓存。
12. **重启 dev Tomcat 会让会话失效**：接口验证前先重新登录，否则拿到的是 `NOT_LOGGED_IN`，容易误判成「改动没生效」。
13. **只读态判定完全依赖 `disabled`**：新增任何表单字段都要同步补 `disabled="disabled"`，否则保存时会带上它。
