# 导出用户修复方案（CSV 格式 + 新增 xlsx）

> 起因：客户/用户反馈导出的用户列表「看着一样却匹配不上」，排查发现是两个格式问题；同时要求新增 xlsx 导出。
> 状态：**已实施并验证**（2026-10-06），待用户确认提交。
> 关联：上一步已完成「用户批量导入」（`devDocs/用户批量导入方案.md`，提交 `09ffeb19c`）。

## 1. 背景与取证（原实现为什么有问题）

原实现：`BussinessController.exportUserList.do` → `exportUserListToCsvFile()` → `LuceneUtil2.buildCsvTitleStrForObject/buildCsvStrForObject`。

```java
case FIELD_TYPE_String:  sb.append(val + "\t,");   // 字符串值后面跟一个 TAB 再跟逗号
case FIELD_TYPE_Integer: sb.append(val + ",");
default:                 sb.append(",");           // null 也直接一个逗号
```

即：**反射全字段**（含 `pwd` 哈希、`serialVersionUID`）+ **每个字符串值尾随 `\t`** + **完全没有引号/转义**。

实测真实导出行（`TAB` 用 `<TAB>` 表示）：

```
4543706613855037637,1,Admin<TAB>,e3afed0047b08059d0fada10f400c1e5<TAB>,2,0,,,,652055239@qq.com<TAB>,1,13777479349<TAB>,1,,,,0,2026-07-31 19:04:01<TAB>,...
```

**`\t` 的后果**：单元格值尾部多一个不可见字符 → Excel 里 `=A2="Admin"` 为 FALSE、`VLOOKUP/COUNTIF/精确匹配` 全部失效；跨系统粘贴/文本导入时 TAB 会被当列分隔符；回灌到不做 trim 的系统会把 TAB 存进账号。

**无转义的后果**：值里出现 `,` → 列错位（实测：造一条 `realName=张三,李四` 的用户，该行逗号数 23 而表头 22 列，按逗号切回来 `realName` 只拿到 `张三`，**其后所有列右移一格**）；`"` → 引号语义破坏；`\n` → 一行拆成多行、行数错乱；行首 `=`/`+` → Excel 当公式执行（CSV 注入）。

**影响面（已核对）**：`userList.csv` 没有被系统迁移/备份等其它流程消费；`buildCsv{Title,}StrForObject` 只有用户导出在用（SalesBase 用的是 `buildDocumentForObject`）→ 但它们仍是 `util` 层通用工具，**本次不改**（反射做不到「去掉某些列」，必须改列白名单）。

## 2. 方案

**改成列白名单式导出**（在 `BussinessController` 内实现，不动 `LuceneUtil2`）：

| 项 | 做法 |
| --- | --- |
| 列集合 | 14 列：`用户ID,用户名,名字,昵称,手机,邮箱,角色,创建方式,创建时间,最后登录时间,最后登录IP,最后登录城市,网络限制,备注`（去掉 `pwd`、`serialVersionUID` 及其它内部字段：`img/emailValid/telValid/docSysType/isSalesServer/role`） |
| 列头 | 中文/英文两套，**跟随界面语言**（前端传 `lang=ch/en`） |
| 角色/创建方式 | 输出**文案**（`普通用户/管理员/超级管理员`；`第一个管理员/自主注册/管理员创建/LDAP登录创建`），英文页输出对应英文 |
| CSV | 标准转义：含 `, " CR LF` 时双引号包裹 + 内部 `"` 变 `""`；**不再输出 `\t`**；UTF-8 + BOM；CRLF 行尾 |
| xlsx | POI `XSSFWorkbook`：**首行加粗 + 冻结首行**、列宽自适应（中文按 2 宽、上限 60）、**所有数据单元格按文本格式写入**（用户ID/手机号不变科学计数法、不丢前导零） |
| 文件名 | 物理文件名 = `userList_yyyyMMddHHmmssSSS.<csv\|xlsx>`（**毫秒**，避免同秒/并发覆盖）；下载名同名；`cleanExpiredUserExportFiles()` 清理 24h 前的 `userList_*` |
| 空结果 | 返回 `没有可导出的用户！`（原来直接报「导出失败」） |
| 入口 | 前端「导出」→ 弹窗选 `导出 CSV` / `导出 Excel` |

**关键耦合**：列头必须与导入别名表**对齐且不冲突** → 导出的文件可直接当导入模板回灌。
实测发现英文列头 `User ID` 归一化后是 `userid`，而导入别名表里把 `userid` 当成账号别名 → 英文导出回灌时「账号」会映射到数字 ID 列 ✗ → **已从导入别名表里去掉 `userid`**（中文「用户ID」归一化是「用户id」，不冲突，可安全忽略）。

## 6. 实施/验证中发现并修掉的问题

1. **英文列头 `User ID` 与导入别名 `userid` 冲突** → 英文导出文件回灌时账号会被映射成数字 ID。已从导入别名表去掉 `userid`（见 §2 关键耦合）。
2. **导出角色文案 `Super Administrator` 导入侧不认识** → 英文导出回灌时 2 条超级管理员行失败（`total 4, skipped 2, failed 2`）。已在 `parseUserType` 补 `superadministrator`/`superuser`，修后 `skipped 4, failed 0`。
3. **同一秒内两次导出会同名覆盖**（实测中文 xlsx 被英文 xlsx 覆盖）→ 文件名时间戳加毫秒。
4. **空结果原来报「导出失败」** → 改为「没有可导出的用户！」。

## 7. 遗留 / 未做

- `LuceneUtil2.buildCsv{Title,}StrForObject`（通用反射 CSV 工具，含 `\t` + 无转义）**保持原样**：当前只有用户导出在用，用户导出已不再依赖它；若将来其它模块要用，需要先修它。
- CSV 里数值型列（`用户ID`）仍是无引号纯数字：**Excel 打开 CSV 时可能把它当数字**（xlsx 已用文本格式规避）；需要严格保真的场景建议用 Excel 导出。
- 未做「导出失败明细 CSV」（D9 的可选项）与「已存在账号→更新」（D3 裁定不做）。
