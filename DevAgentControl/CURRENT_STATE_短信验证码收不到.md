- 258ms 说明**请求真实到达云片并有响应** → 不是网络/签名/装配问题。
- 云片的成功判定 = 响应 `code == 0`（`YunpianSmsProvider.java:25`）—— 语义是 **「提交/受理成功」，不等于送达**。

### 2. 当前短信配置（`system_setting` 表，脱敏读取）

| 项 | 值 |
| --- | --- |
| `sms.enabled` / `sms.provider` | `true` / `yunpian` |

| `sms.scenes` | `register` / `resetPwd` / `phoneVerify` / `test` **四个场景 tplId 全是 `1341175`** ⚠️、`vars=["code"]` |
| `sms.aliyun` | accessKeyId / accessKeySecret 均为空 |

- 模板 `1341175` 是云片**官方示例模板**：`JavaSmsApi.java:56` 注释写「1号模板:【#company#】您的验证码是#code#」，而 `:62` 里 `#company#=自由团队` **被注释掉**了 → 只发 `#code#` ⇒ 内容里**签名为空**（「【】您的验证码是123456」）。
- 用该 key 只读查云片（`/v2/user/get.json`）→ `code=-3 IP没有权限` ⇒ 该账号**开了 IP 白名单**（或该 key 权限受限），所以**拿不到状态报告，只能在云片控制台看**。

## 定性结论

- **系统发送链路正常**：配置读取 → 模板变量渲染 → 云片 API 调用 → 响应解析 全部走通，`code=0` 已被正确判为成功。
- 未送达的原因在**云片通道 / 运营商 / 手机侧**（已向云片提交客服单）。
- 一个**仍未排除的配置隐患**（不影响本次定性，但客户上线前必须处理）：现在用的是**云片示例 key + 示例模板**，不是客户自己申请的；示例模板需要 `#company#`（签名）变量而我们只发 `#code#`。
