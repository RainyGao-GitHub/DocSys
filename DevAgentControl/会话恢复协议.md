# 会话恢复与工作卡协议

> **启用前提**：工程根目录存在 `CURRENT_STATE_*.md`。
> 根目录没有卡 = 本协议整体不适用，**不要执行其中任何步骤**（`DevAgentControl/` 下的卡只是档案）。

## 1. 会话恢复（每会话 / 每次上下文压缩后）

`CLAUDE.md` 每个会话都会被重新注入，但上下文压缩会丢失当前任务、参考计划、当前进展与生效约束——这些一律以**根目录那张工作卡**为准。

1. **读根目录的工作卡**：它是当前任务信息的唯一定义处（必读上下文、参考计划与上下文、当前进展、生效约束，含是否需要先提交、是否已获用户裁定）。
2. **按卡内锚点续接**：读卡里列出的必读上下文与计划/上下文文档的指定锚点（不必全文重读）。
3. 完成后才开工。

卡里写明「用户尚未裁定 / 不要自行改代码」时，**先问用户**，不要开工。

## 2. 工作卡更新时机：里程碑驱动（不是压缩驱动）

**模型侧观察不到「即将压缩」**（无上下文余量指标、无预警信号），所以「压缩前抢救一次」的约定等于永不触发。改为**里程碑驱动**：出现下列任一事件，**立即**更新工作卡，不攒批、不等收尾。

- 定位到根因（写清根因 + 证据位置）
- 得到验证结果（PASS/FAIL 数字、realDiff、字节差等具体值）
- 一个子项结论**成立或被推翻**（被推翻时必须删改原结论，不留过期描述）
- 用户给出裁定 / 纠正 / 确认
- 提交代码（记 commit 号与归属仓库）
- 开始新子任务或切换子项

更新落到卡的「当前进展」「下一步」「未提交改动」三处。这样卡永远最多落后一个里程碑——压缩何时发生、压缩是否失败、是否换新会话，都能从卡无损续接。

## 3. 如实性要求

卡里的状态描述必须与实际完成范围一致：

- 完成子项 1 不得写成「该缺陷已修复」
- 未验证的不得写「已验证」
- FAIL 要写明数字和归因

宁可写「未完成 / 未验证」，不可夸大——下个会话会把卡当事实续接。

## 4. 启用 / 停止

- **启用**：把 `DevAgentControl/CURRENT_STATE_xxx.md` 移到工程根目录（或直接在根目录新建，模板见下）。
- **停止**：任务收尾后把卡移入 `DevAgentControl/已完成/`，根目录不再有 `CURRENT_STATE_*.md` → 模式自动关闭。

## 5. 卡片模板

```markdown
# CURRENT_STATE_<任务名>

- 建立日期：
- 状态：进行中 / 挂起

## 必读上下文
- <文件路径 + 只看哪一段>

## 参考计划与上下文
- <计划文档路径>（续接锚点：<章节/小节>）

## 当前进展
- <已完成到什么程度；未验证的明确写「未验证」>

## 下一步
1. <具体动作>

## 生效约束
- <例：用户尚未裁定是否实施 → 不要自行开工改代码，先问用户>
- <例：开工前是否先提交、提交哪些>

## 未提交改动
- <仓库 / 文件 / 状态；已提交则记 commit 号>
```
